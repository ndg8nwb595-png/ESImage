## 1. 产品概述

### 1.1 背景

电商商家与运营人员需要为主图、详情图准备大量视觉素材，但多数人没有设计基础，也不会使用 Photoshop 等工具。传统方式要么依赖美工排期，要么使用模板工具反复手工调整，成本高、产出慢。

本系统通过「自然语言对话 + 简单参数选择 + AI 图生图」的方式，让不会设计的人也能为自己的商品生成可上架的主图与详情图。

### 1.2 产品定位

- **形态**：内部工具（公司/团队内部使用），不对外开放注册、不做付费与计费。
- **核心**：用户端「生成电商主图/详情图」的体验与专业度。
- **支撑**：管理后台满足账号、权限、内容追溯、配置与审计需要，不追求复杂运营功能。

### 1.3 目标用户

| 用户类型 | 描述 | 主要诉求 |
| --- | --- | --- |
| 普通用户 | 运营、客服、店主等没有设计基础的人 | 快速生成能上架的主图/详情图 |
| 管理员 | 负责账号、模板、素材、提示词等日常维护的人 | 管账号、管内容、看使用情况 |
| 超管 | 系统负责人/运维负责人 | 全量数据、模型配置、日志与导出 |

### 1.4 核心价值

1. **降低门槛**：不需要懂提示词，通过商品名称、风格、尺寸和聊天即可出图。
2. **结果可用**：基于用户上传的真实商品图做图生图，文字由后端合成，避免模型画错中文。
3. **过程可控**：先生成一张示例图，用户确认风格后再批量生成，减少整组返工。
4. **全程可追溯**：管理员能查到任意用户的会话、每次 Agent 调用、每张图的参数与结果。

### 1.5 本期目标

本期以「主链路可用、管理可追溯」为验收目标，不设付费、增长类指标。核心验收口径见第 12 章。

## 3. 角色与权限

### 3.1 角色定义

系统固定三个内置角色，不允许新建角色：

| 角色 | 标识 | 职责 |
| --- | --- | --- |
| 普通用户 | `user` | 使用创作台、历史作品、个人中心 |
| 管理员 | `admin` | 管理用户、模板素材、系统提示词、内容追溯、Token 统计 |
| 超管 | `super_admin` | 拥有管理员全部权限，另加模型配置、操作日志、全量数据导出 |

### 3.2 角色组合规则

- 一个账号可拥有 **1~2 个角色**。
- 允许的组合：
  - 仅普通用户
  - 仅管理员
  - 仅超管
  - 管理员 + 普通用户
  - 超管 + 普通用户
- **禁止**的组合：
  - 超管 + 管理员
  - 超管 + 管理员 + 普通用户
- 超管的权限**包含管理员全部权限**。
- 仅拥有管理员或超管角色的账号，**不能进入创作台**；要使用创作能力，必须同时拥有普通用户角色。

### 3.3 权限矩阵

| 功能 | 普通用户 | 管理员 | 超管 |
| --- | --- | --- | --- |
| 创作工作台 | ✓ | 仅当同时拥有用户角色 | 仅当同时拥有用户角色 |
| 历史作品 | ✓ | 仅当同时拥有用户角色 | 仅当同时拥有用户角色 |
| 个人中心 | ✓ | 仅当同时拥有用户角色 | 仅当同时拥有用户角色 |
| 管理后台入口 | ✗ | ✓ | ✓ |
| 概览 / Token 统计 | ✗ | ✓ | ✓ |
| 用户管理 | ✗ | ✓（不含超管、不含自己角色） | ✓ |
| 角色与权限点管理 | ✗ | ✗ | ✓（可编辑） |
| 内容追溯（聊天/生图） | ✗ | ✓ | ✓ |
| 素材与模板 | ✗ | ✓ | ✓ |
| 系统提示词 | ✗ | ✓ | ✓ |
| 模型配置 | ✗ | ✗ | ✓ |
| 操作日志 | ✗ | ✗ | ✓ |
| 数据导出 | ✗ | ✗ | ✓ |

### 3.4 权限点规则

- 权限点粒度：**菜单级 + 关键操作级**（如删除账号、重置密码、修改配置、导出数据）。
- 管理员与普通用户的权限点由**超管**在「账号与权限 → 角色管理」中勾选配置。
- 管理员**不能**编辑权限点。
- 超管**不依赖角色权限配置**：系统始终赋予超管全部权限，避免误配置导致超管被锁死。
- 所有后端接口必须按权限点校验，不能只靠前端隐藏菜单。

### 3.5 账号边界

1. 管理员可以新建、编辑、禁用、软删除普通用户和管理员。
2. 管理员**不能**创建、修改、禁用、删除超管账号。
3. 管理员**不能**修改自己的角色。
4. 超管**不能**删除或禁用自己。
5. 系统必须至少保留一个可用的超管账号。
6. 账号删除为**软删除**：账号不能登录，历史数据保留，超管可恢复。
7. 用户名唯一，删除后仍占用原用户名，不可被新账号复用。

## 4. 总体业务流程

### 4.1 用户端主流程

```
登录
  ↓
创作工作台
  ↓
填写参数（仅商品名称必填；风格、尺寸选填）
  ↓
可选：上传 1~5 张商品图
  ↓
前端校验（商品名称未填则弹窗拦截，不发送请求）
  ↓
可选：在聊天区补充卖点、人群、语气等需求（调用轻链路 Agent）
  ↓
点击「生成示例图」→ 完整 8 Agent 链
  ↓
示例图返回
  ↓
┌─────────────┬──────────────┬──────────────┐
│ 重新生成示例 │ 调整参数后重来 │ 确认并生成全套 │
└─────────────┴──────────────┴──────────────┘
  ↓（确认）
批量生成剩余图片
  ↓
结果区预览 / 单张下载 / 整组 ZIP / 重生成某张
  ↓
历史作品（只读）
```

### 4.2 生成流程（两段式）

1. **示例阶段**：生成 **1 张主图**作为设计风格示例图，用于确认风格、版式、商品还原度。
2. **确认阶段**：用户可以：
   - 重新生成示例图（仍为主图）；
   - 调整参数后重新生成示例图；
   - 确认示例图并生成全套。
3. **批量阶段**：确认后，示例图（主图）计入正式结果，系统生成 **5 张详情图**：
   - 主图：共 **1 张**（即示例图，不重复生成）。
   - 详情图：共 **5 张**。
   - 全套合计 **6 张**。
4. **结果阶段**：结果区展示整组图片，支持预览、下载、单张重生成、取消任务。

### 4.3 管理端追溯流程

```
管理员登录 → 管理后台
  ↓
概览（用户数 / 今日生成 / 累计图片 / 今日 Token）
  ↓
账号与权限 → 用户列表 → 用户详情
  ↓
内容追溯 → 按用户 → 会话 → 生成批次 → 单张图
  ↓
查看参数、提示词、模型、耗时、Token、状态、图片
  ↓
聊天记录 → 展开 Agent 中间调用明细
```

### 4.4 开号与登录流程

1. 管理员在「账号与权限 → 用户管理」新建账号：用户名、显示名、初始密码、角色（按组合规则校验）、状态。
2. 管理员线下把账号与初始密码告知用户。
3. 用户使用用户名 + 密码登录，可勾选「记住我」。
4. 用户可在个人中心修改密码；忘记密码由管理员重置。
5. 登录后按角色进入：
   - 普通用户：直接进入创作工作台；
   - 仅管理员/仅超管：进入管理后台；
   - 双角色：顶部可在「创作台 / 管理后台」之间切换。

## 5. 用户端功能总览

### 5.1 登录

- 居中卡片登录页，包含系统名称/Logo、用户名、密码、记住我、登录按钮、错误提示。
- 不提供注册、忘记密码入口。
- JWT 默认 24 小时有效；勾选「记住我」为 7 天。
- 登录失败提示统一为「用户名或密码错误」，不区分账号是否存在。
- 未登录访问受保护页面时跳转登录页，登录后回到原页面。

### 5.2 创作工作台

**布局**：三栏。

- 左栏：会话列表。
- 中栏：聊天框（消息流、输入框）。
- 右栏：上方参数面板 + 商品图上传 + 模板独立入口，下方结果区（示例图、结果网格、操作按钮）。

**参数面板（精简字段）**：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 商品名称 | 是 | 用户手工填写；商品类目由商品理解 Agent 推断 |
| 风格 | 否 | 自由文本；不填时由对话 Agent 推荐，用户可自然语言选择或自行补充 |
| 尺寸 | 否 | 不选时默认 1:1、1000×1000；可选平台预设或自定义 |
| 商品图 | 否 | 1~5 张，JPG/PNG/WEBP，单张 ≤10MB |

**模板入口**：独立于参数面板的模板卡片区，点击即应用模板；模板由管理员维护。

> 参数与上传图 ID 由前端 localStorage 保存；刷新/切换会话可恢复，换设备或清缓存会丢失。

**前端校验**：商品名称为空时，点击生成或发送聊天均被拦截，弹窗提示，**不发送任何网络请求**；其余字段均为选填。

### 5.3 历史作品

- 只读列表，按生成时间倒序。
- 仅展示**最终成功**的正式图；示例图、失败图、取消任务的半成品不进入历史。
- 支持预览大图、单张下载、整组 ZIP 下载。
- 不提供删除、编辑、收藏、分组、关键词搜索。

### 5.4 个人中心

- 查看/修改显示名、邮箱（选填）；头像本期不做。
- 修改登录密码（需验证旧密码）。
- 用户名不可修改，由管理员分配。

## 6. Agent 体系

### 6.1 Agent 清单（8 个）

| 编号 | Agent | 职责 | 关键输入 | 关键输出 | 核心 |
| --- | --- | --- | --- | --- | --- |
| 1 | 规划 Agent | 判断聊天意图、拆解 1 主图 + 5 详情图、编排调用顺序 | 参数、会话摘要、聊天意图 | 任务计划（6 张图的角色、主题、调用顺序） | 是 |
| 2 | 商品理解 Agent | 推断类目、卖点、人群、场景；调用素材检索工具 | 商品名称、上传图、对话摘要 | 商品画像、素材候选 | 是 |
| 3 | 文案 Agent | 生成主图/分图文案 | 商品画像、风格、模板 | 标题、卖点、说明文案 | 是 |
| 4 | 提示词 Agent | 生成每张图的生图参数与留白区 | 文案、风格、尺寸、素材 | 结构化提示词 JSON | 是 |
| 5 | 生图执行 Agent | 调用豆包 Seedream 完成图生图 | 提示词、参考图 | 图片文件 | 是 |
| 6 | 质量审核 Agent | 检查文字错乱、主体变形、合规 | 图片、文案 | 审核结论与问题列表 | 否 |
| 7 | 修复 Agent | 根据审核问题修正提示词并触发重生成 | 审核问题、原提示词 | 修正后的提示词 | 否 |
| 8 | 平台规范 Agent | 校验尺寸、违禁词、类目规则 | 文案、参数、图片、平台规范提示词 | 规范检查结论 | 否 |

> 「素材检索」是商品理解 Agent 内部调用的工具，不单独计为 Agent。

### 6.2 生成全链路

```
规划 → 商品理解（含素材检索）→ 文案 → 提示词 → 生图执行
                                                    ↓
                                              质量审核
                                                    ↓
                                    ┌───────────────┴───────────────┐
                                    │ 通过                          │ 不通过
                                    ↓                               ↓
                                 平台规范                         修复 → 重新生图
                                    ↓
                                 文字合成
                                    ↓
                                 输出结果
```

### 6.3 聊天轻链路

- 用户在聊天区每发一条消息，只调用「规划 Agent + 商品理解 Agent」做理解、追问与需求摘要更新。
- 聊天轻链路**不生成图片**，也不调用文案/提示词/生图/审核/修复/平台规范 Agent。
- 点击「生成示例图」时才触发完整 8 Agent 链。
- 聊天回复采用 **SSE 流式输出**。
- 会话上下文 = 最近 10 轮对话 + 当前参数 + 已确认示例图。

### 6.4 失败与降级

1. 除生图执行 Agent 外，每个 Agent 调用失败自动重试 **10 次**，采用指数退避（1s → 2s → 4s → 8s → 16s → 30s 封顶）。
2. 生图执行 Agent 每张最多尝试 **2 次**；2 次均失败，**整个任务立即失败**。
3. 其他 Agent 重试 10 次仍失败时：
   - **非核心 Agent**（质量审核、修复、平台规范、素材检索）跳过，并在任务中标记「未校验/未修复/未使用素材」。
   - **核心 Agent**（规划、商品理解、文案、提示词）失败则终止任务，提示用户卡在哪一步。
4. 非生图原因导致的单张失败，标记该张失败，其余继续；重试或重生成均**新增生成记录**，旧图保留。

## 7. 生图与文件

### 7.1 生成参数

- 图片构成：每次生成固定为 **1 张主图 + 5 张详情图**，共 6 张；不再区分“主图模式/详情图模式”。
- 尺寸：不选择时默认 **1:1、1000×1000**；保留平台预设（淘宝/京东/拼多多/抖音等）与自定义宽高。
- 风格：用户自由文本填写；不填时由对话 Agent 推荐，用户可自然语言选择或自行补充；后台不维护风格配置。
- 模板：管理员维护，用户端以卡片形式展示启用中的模板。
- 商品图：可选 1~5 张，作为图生图参考；不传时走纯文生图。

### 7.2 张数

| 图片角色 | 示例图 | 确认后批量 | 合计 |
| --- | --- | --- | --- |
| 主图 | 1 张（即示例图） | 0 张 | 1 张 |
| 详情图 | 0 张 | 5 张 | 5 张 |
| 合计 | 1 张 | 5 张 | 6 张 |

### 7.3 文字渲染

- 生图时要求模型在画面中**留出文字区**。
- 文案由后端使用中文字体与版式合成到留白区，确保文字正确、可控。
- 版式由后续产出的「设计 Skill」驱动；本阶段 PRD 只定义契约：
  - 输入：文案块（标题、卖点、说明）、版式指令（位置、字号、颜色、对齐）、底图；
  - 输出：合成后的图片。
- 不在本期实现用户自选字体、颜色、字号。

### 7.4 图片存储

- 存储：MinIO。
- 文件类型：
  - 用户上传的商品原图；
  - 生成的正式图；
  - 生成过程图（示例图、失败图、取消前半成品）；
  - 列表缩略图。
- 所有图片文件长期保留，随业务数据执行 5 年热存 + 归档策略。

### 7.5 内容安全

- 上传时校验格式、大小、分辨率。
- 生成前后使用豆包平台自带内容审核。
- 平台规范 Agent 检查违禁词与类目规则。
- 不建人工审核队列。
- 审核不通过时：任务标记失败并提示用户调整描述或更换商品图，不自动反复重试。

## 11. 状态机与边界规则

### 11.1 生成任务（`generation_batches`）状态

批次分为两类：`sample`（示例批次）与 `full`（全套批次）。

**示例批次**：

```
queued → running → sample_ready → confirmed
                 ↘ failed
queued / running / sample_ready → cancelled
```

- `sample_ready`：示例图已出，等待用户确认或重新生成。
- `confirmed`：用户已确认该示例，系统据此创建 `full` 批次。
- 重新生成示例会创建新的 `sample` 批次，旧批次保留可追溯。

**全套批次**：

```
queued → running → completed / partially_failed / failed
queued / running → cancelled
```

- `full` 批次必须通过 `source_sample_batch_id` 引用一个已确认的 `sample` 批次。
- 被引用的示例图作为 `full` 批次的第一张正式图，不重复生成。

### 11.2 单张图（`generated_images`）状态

`pending → generating → success / failed / cancelled`

- 失败图可单独重试，重试生成新记录。
- 取消任务时，已生成成功的图片保留并标记为 `cancelled` 任务下的产物，不进入历史作品。

### 11.3 会话（`creative_sessions`）状态

`active → hidden`（用户软删除）

- 软删除仅影响用户自己的会话列表，不影响后台追溯。
- 管理员仍可查看该会话的聊天与生图记录。

### 11.4 账号（`users`）状态

`active → disabled → deleted`（软删除）

- `disabled`：不能登录，数据保留，可恢复。
- `deleted`：不能登录，数据保留，超管可恢复；用户名不可复用。

### 11.5 关键边界清单

1. 参数未填齐，前端拦截，不发任何请求。
2. 商品名称未填时聊天框禁用；填写后聊天只走轻链路。
3. 商品图最多 5 张，单张 ≤10MB，仅 JPG/PNG/WEBP。
4. 重生成、重试均新增记录，不覆盖旧图。
5. 历史作品只展示最终成功图。
6. 聊天记录只读 + 搜索，不导出。
7. 管理员不能操作超管账号与自己角色。
8. 超管不能删除/禁用自己，系统至少保留一个可用超管。
9. 删除账号为软删除，历史数据保留。
10. 5 年热数据到期自动转 `archive/` 归档前缀，不删除。
11. 内容审核不通过不自动反复重试。
12. 单用户同时只运行 1 个 `queued` / `running` 生成任务；`sample_ready` 不计入。
13. 参数面板与上传图 ID 不落库，由前端 localStorage 保存；换设备/清缓存会丢失。

## 12. 验收标准

### 12.1 功能验收

| 模块 | 验收要点 |
| --- | --- |
| 登录 | 正确账号可登录；错误提示不泄露账号是否存在；记住我 7 天；无注册/找回入口 |
| 创作工作台 | 只有商品名称必填，其余选填；商品名称未填不发请求；上传 1~5 张并校验；模板入口可用；三栏布局 |
| 聊天 | 商品名称填写后可聊；SSE 流式；只调规划+商品理解；10 轮上下文；会话自动命名/重命名/软删除 |
| 生图 | 示例图（即主图）→ 确认 → 批量；1 张主图 + 5 张详情图；失败重试与降级；进度分阶段；取消任务 |

| 历史作品 | 只读、仅最终成功图、单张/整组下载、不提供删除 |
| 账号权限 | 三级固定角色、组合校验、超管权限包含管理员、管理员不能碰超管与自己角色、至少保留一个超管 |
| 管理后台 | 6 个菜单按权限可见；用户/角色/内容追溯/素材模板/Agent 配置/日志/导出均可用 |
| 数据追溯 | 用户 → 会话 → 批次 → 单图；可看参数、提示词、模型、耗时、Token、图片 |
| 导出 | 仅超管；ZIP + CSV；按会话分目录 |
| 保留策略 | 5 年热存；到期转`archive/` 归档前缀；不删除 |

### 12.2 非功能验收

1. 单机 Docker Compose 可一键启动全部服务。
2. PostgreSQL、Redis、MinIO 数据卷持久化，重启不丢数据。
3. 每日备份任务执行成功，备份可恢复。
4. 上传文件类型、大小、数量后端二次校验。
5. 所有后台接口做权限校验，越权返回 403。
6. 密码使用 bcrypt 等不可逆算法存储；API Key 加密存储。
7. 应用日志保留 90 天；操作日志可查。
8. 前端在 1280×720 及以上分辨率可用。

## 14. 开发与交付约束

1. **AI 代码生成只能使用 DeepSeek，禁止使用 Codex/GPT 写代码。**
2. 所有代码注释、文档、测试日志使用中文；专有名词保留英文。
3. 严格按 PRD 实现，不增加 PRD 之外的功能，不遗漏 PRD 提到的功能。

5. 架构相关调整必须先与产品负责人确认，不得私自决定。
6. 模块尽量独立，便于维护和替换。
7. 优先复用成熟依赖库；无现成能力时再自行实现。
8. 在不影响需求的前提下优化计算与调用次数，避免不必要的模型调用。

10. 测试代码每一步加中文日志，便于排查。
