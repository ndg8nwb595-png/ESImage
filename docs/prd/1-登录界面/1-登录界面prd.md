## 1. 文档目的与范围

### 1.1 目的

定义用户进入系统的唯一入口：登录页的布局、字段校验、登录流程、登录态管理、路由守卫与按角色跳转。

### 1.2 本期范围

- 登录页展示与交互。
- 用户名 + 密码登录。
- 「记住我」。
- JWT 登录态、请求携带、过期处理。
- 路由守卫与角色入口分流。
- 退出登录。
- 登录成功/失败的审计日志。

### 1.3 不做

- 自助注册。
- 忘记密码、邮箱/短信验证码。
- 图形验证码、登录失败锁定。
- 单点登录（SSO）、多因素认证（MFA）。
- 第三方登录。

> 账号由管理员开设，密码由管理员重置；相关规则见 `6-管理后台-账号与权限prd.md`。

## 3. 字段与校验

| 字段 | 必填 | 规则 | 校验时机 |
| --- | --- | --- | --- |
| 用户名 | 是 | 4~20 位；字母、数字、下划线；首尾空格自动去除；区分大小写 | 失焦 + 提交 |
| 密码 | 是 | 8~32 位；不做复杂度要求；**不去除空格** | 失焦 + 提交 |
| 记住我 | 否 | 布尔值，默认 `false` | 提交时读取 |

### 3.1 前端校验规则

1. 用户名为空：提示「请输入用户名」。
2. 用户名格式不符：提示「用户名需为 4~20 位字母、数字或下划线」。
3. 密码为空：提示「请输入密码」。
4. 密码长度不符：提示「密码长度需为 8~32 位」。
5. 前端校验不通过时，**不发送登录请求**。
6. 提交过程中按钮禁用，防止重复提交。

### 3.2 后端校验

后端必须再次校验字段格式与账号状态，不能只依赖前端。校验失败返回参数错误码。

## 4. 登录流程

### 4.1 正常流程

```
用户输入用户名、密码
        ↓
前端校验
        ↓（通过）
POST /api/v1/auth/login
        ↓
后端校验账号、密码、状态
        ↓（成功）
返回 token、过期时间、用户信息与权限
        ↓
前端保存 token
        ↓
按角色跳转
```

### 4.2 请求与响应

**请求**

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "zhangsan",
  "password": "******",
  "remember_me": false
}
```

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "<jwt>",
    "expires_at": "2026-11-01T10:00:00+08:00",
    "user": {
      "id": 1,
      "username": "zhangsan",
      "display_name": "张三",
      "avatar_url": null,
      "roles": ["user"],
      "permissions": ["user.workspace", "user.history", "user.profile"]
    }
  }
}
```

**失败响应**

```json
{
  "code": 20001,
  "message": "用户名或密码错误",
  "data": null
}
```

### 4.3 登录失败处理

| 情况 | 前端提示 | 是否泄露账号存在 |
| --- | --- | --- |
| 用户名或密码错误 | 用户名或密码错误 | 否 |
| 账号被禁用 | 用户名或密码错误 | 否 |
| 账号已删除 | 用户名或密码错误 | 否 |
| 参数格式错误 | 对应字段提示 | — |
| 网络异常 | 网络异常，请稍后重试 | — |
| 服务端异常 | 系统繁忙，请稍后重试 | — |

> 统一使用「用户名或密码错误」，避免通过错误提示判断账号是否存在。账号状态由管理员在后台查看。

### 4.4 记住我

| 选项 | Token 有效期 |
| --- | --- |
| 未勾选 | 24 小时 |
| 勾选 | 7 天 |

- 有效期由后端在签发 JWT 时写入 `exp`。
- 「记住我」只影响 token 有效期，不影响其他权限。
- 前端不额外保存用户名密码。

### 4.5 登录成功后的跳转

| 账号角色 | 默认落地页 |
| --- | --- |
| 仅普通用户 | `/workspace` |
| 仅管理员 | `/admin/dashboard` |
| 仅超管 | `/admin/dashboard` |
| 管理员 + 普通用户 | `/workspace` |
| 超管 + 普通用户 | `/workspace` |

- 双角色账号登录后默认进入创作台，顶部提供「创作台 / 管理后台」切换。
- 若登录前访问的是受保护页面，登录成功后优先回跳原页面；回跳地址必须是站内路径，禁止开放重定向。

## 5. 登录态与路由守卫

### 5.1 Token 存储

- 前端将 JWT 保存在 `localStorage`，键名 `esimage_token`。
- 所有后端请求通过请求头携带：

```http
Authorization: Bearer <token>
```

- 聊天 SSE 使用 `fetch` + `ReadableStream` 读取流式响应，不使用原生 `EventSource`，以便携带 `Authorization` 请求头。
- JWT 载荷：`sub`（用户 ID）、`exp`、`iat`、`token_version`、`roles`、`permissions`。其中 `roles`/`permissions` 仅用于前端渲染导航；后端鉴权每次请求读取服务端状态（Redis 缓存 ≤30 秒，变更时主动失效），以服务端为准。

### 5.2 登录态校验

1. 应用启动时读取 `localStorage` 中的 token。
2. 无 token：跳转 `/login`。
3. 有 token：调用 `GET /api/v1/auth/me` 获取当前用户与权限。
4. 返回 401：清除 token，跳转 `/login?redirect=<原路径>`。
5. 返回 403：跳转 `/403`。
6. 返回成功：写入全局用户状态，按角色渲染导航。

### 5.3 路由守卫规则

| 路由 | 要求 |
| --- | --- |
| `/login` | 未登录可访问；已登录访问时按角色跳转默认页 |
| `/workspace` | 需要 `user.workspace` 权限 |
| `/history` | 需要 `user.history` 权限 |
| `/profile` | 需要 `user.profile` 权限 |
| `/admin/*` | 需要对应管理菜单权限；无权限跳 `/403` |
| `/403` | 已登录可访问 |
| 不存在路由 | 跳 `/404` |

### 5.4 请求拦截

- 所有 `fetch` 请求统一注入 `Authorization` 头。
- 收到 401：清除 token，跳转登录页。
- 收到 403：展示无权限页面，不跳登录页。
- 收到 5xx：展示统一错误提示，不自动登出。

### 5.5 退出登录

1. 用户点击右上角「退出登录」。
2. 前端调用 `POST /api/v1/auth/logout`（用于记录审计日志，服务端不强制维护黑名单）。
3. 前端清除 `localStorage` 中的 token 与全局用户状态。
4. 跳转 `/login`。

> 本期 JWT 为无状态令牌，退出登录以客户端清除为准；如需强制下线，由管理员禁用账号实现，后端在每次请求时校验账号状态。

## 6. 角色入口

### 6.1 顶部导航

| 账号角色 | 顶部导航内容 |
| --- | --- |
| 普通用户 | 创作台、历史作品、个人中心、退出登录 |
| 管理员 | 管理后台、退出登录（若同时有用户角色，增加「创作台」切换） |
| 超管 | 管理后台、退出登录（若同时有用户角色，增加「创作台」切换） |
| 管理员 + 用户 | 创作台 / 管理后台切换、历史作品、个人中心、退出登录 |
| 超管 + 用户 | 创作台 / 管理后台切换、历史作品、个人中心、退出登录 |

### 6.2 双角色切换

- 顶部提供「创作台 / 管理后台」切换控件。
- 切换不重新登录，直接路由跳转。
- 当前所在端高亮显示。
- 仅管理员或仅超管账号不显示「创作台」入口。

## 8. 安全要求

1. 密码使用 bcrypt（cost=12）不可逆算法存储，禁止明文或可逆加密。
2. JWT 使用 HS256（PyJWT 实现），密钥通过环境变量注入，不得写入代码仓库。
3. 登录接口必须记录审计日志：用户名、时间、IP、User-Agent、结果（成功/失败），失败不记录密码。
4. 登录失败提示不得区分账号是否存在。
5. 前端不得在日志、错误上报中输出密码或 token。
6. 后端在每次请求时校验账号状态；账号被禁用/删除后，已签发 token 立即失效。
7. 生产环境建议启用 HTTPS；若仅内网 HTTP，需在网络层限制访问范围。
8. 本期不做登录失败锁定与验证码，需在部署文档中标注该风险。

## 10. 验收标准

1. 输入正确用户名和密码可登录，并按角色跳转到正确页面。
2. 用户名/密码为空或格式错误时，前端拦截且不发送请求。
3. 用户名不存在、密码错误、账号禁用、账号删除，均提示「用户名或密码错误」。
4. 未勾选「记住我」token 有效期为 24 小时；勾选后为 7 天。
5. 未登录访问 `/workspace`、`/history`、`/profile`、`/admin/*` 时跳转登录页。
6. 登录后回跳原页面；`redirect` 为站外地址时忽略并进入默认页。
7. 管理员/超管登录后进入管理后台；双角色账号进入创作台并可切换。
8. 退出登录后 token 清除，再次访问受保护页面需重新登录。
9. 登录成功与失败均写入审计日志，失败日志不含密码。
10. 账号被禁用后，旧 token 请求返回 401/403，前端回到登录页。

## 12. 技术选型（细化）

| 层 | 选型 |
| --- | --- |
| 前端路由 | React Router v6 |
| 前端状态管理 | zustand |
| 前端请求层 | 自封装 fetch（统一注入 token、处理 401/403/5xx；SSE 用 fetch + ReadableStream） |
| 后端 JWT | PyJWT，HS256；载荷含 `sub`/`exp`/`iat`/`token_version`/`roles`/`permissions` |
| 密码哈希 | bcrypt（cost=12） |
| 鉴权校验 | 账号状态与权限走 Redis 缓存 ≤30 秒，变更时主动失效；`token_version` 递增使旧 token 失效 |
| Token 刷新 | 本期无 refresh token：默认 24h、记住我 7d，过期需重新登录（已知限制） |
