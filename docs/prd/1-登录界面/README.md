## 1. 最小 demo 范围

### 1.1 做

- 登录页：用户名、密码、记住我、前端校验、错误提示、提交 loading。
- `POST /api/v1/auth/login`：账号密码校验、JWT 签发、24h/7d 有效期、统一失败提示、登录审计。
- `GET /api/v1/auth/me`：刷新后恢复用户、角色与权限。
- `POST /api/v1/auth/logout`：写退出审计，前端清理登录态。
- Token 存 `localStorage`，键名 `esimage_token`；所有请求带 `Authorization: Bearer`。
- 路由守卫、401/403/5xx 处理、站内 redirect 安全回跳。
- 角色默认落地页：普通用户 `/workspace`，管理员 `/admin/dashboard`，双角色 `/workspace` 且可切换。
- 账号禁用/删除、`token_version` 递增后旧 token 失效。

### 1.2 不做

- 自助注册、忘记密码、邮箱/短信验证码。
- 图形验证码、登录失败锁定。
- SSO、MFA、第三方登录。
- refresh token。
- 管理后台的账号 CRUD、角色权限编辑、操作日志查询页面。
- 生图、聊天、历史作品、个人中心等业务功能（仅保留路由占位页）。

### 1.3 相对 PRD 的最小化取舍

| PRD 要求 | 最小 demo 处理 | 原因 |
| --- | --- | --- |
| 权限/账号状态走 Redis 缓存 ≤30 秒 | 每次请求直接查 PostgreSQL | 不引入 Redis，行为更严格（即时生效），不影响登录演示 |
| Alembic 迁移 | 建表脚本 + 幂等种子脚本 | 减少工程搭建成本 |
| 18 张表 | 只建登录链路需要的 6 张 | 其余表与登录无关 |
| 23 个权限点 | 只种登录演示用到的权限点 | 生成、管理后台功能不在 demo 内 |
| 超管账号 | 不预置；超管落地页与管理员相同 | 角色分流逻辑可被管理员覆盖 |
| bcrypt cost=12、JWT HS256、审计日志 | 保留 | 属于 1 号 PRD 的硬性安全要求 |

## 4. 验收总口径

最小 demo 完成时，至少能完整演示以下路径：

1. `demo_user` 登录 → 进入 `/workspace` → 刷新仍保持登录 → 退出 → 回 `/login`。
2. `demo_admin` 登录 → 进入 `/admin/dashboard`；访问 `/workspace` 被守卫处理。
3. `demo_dual` 登录 → 进入 `/workspace` → 顶部切换到 `/admin/dashboard` → 切回。
4. 未登录直接访问 `/workspace` → `/login?redirect=/workspace`；登录后回跳。
5. 勾选「记住我」后 JWT `exp` 为 7 天，未勾选为 24 小时。
6. 用 SQL 把 `demo_user` 置为 `disabled` → 旧 token 请求失败 → 前端回登录页。
7. 登录成功与失败都能在 `audit_logs` 中查到，失败记录不含密码。

## 5. 待确认项

以下事项在接口文档中给出了 demo 默认口径，正式实现前需要与 8 号、9 号文档统一：

1. 账号禁用/删除后，已登录请求的 HTTP 状态与错误码（本文档采用 `403 + 20004`，前端对 `20004` 特判回登录）。
2. 登录/退出审计的动作码（本文档暂用 `auth.login`、`auth.logout`）。
3. 登录响应与 `/auth/me` 响应的 `user` 结构差异（分别遵循 1 号与 9 号文档）。
4. `avatar_url` 在最小 demo 中固定为 `null`，正式实现由 `avatar_path` 转换。
