## 1. 最小 demo 范围

### 1.1 做

- PostgreSQL 16 基线：UTF-8、Asia/Shanghai、`snake_case`、`BIGSERIAL` 主键、`TIMESTAMPTZ`、`JSONB` 快照、`ON DELETE RESTRICT`、软删除。
- 10 号 §4 的 18 张业务表：字段、类型、空值、默认值、`CHECK` 约束、唯一约束、部分唯一索引、普通索引与实体关系。
- Alembic 版本化迁移：`upgrade head` / `downgrade base` 可正反向执行；迁移脚本不删除业务数据。
- 幂等种子：3 个角色、23 个权限点、角色权限矩阵、4 条尺寸预设、8 个 Agent 的初始提示词与版本 1、1 条启用的模型配置（API Key 为空）。
- 首个超管初始化：通过显式环境变量设置用户名与密码，bcrypt 存储；未设置或使用弱默认密码时拒绝执行，不静默生成账号。
- 会话、消息、Agent 调用三条写入链路的数据契约：`client_message_id` 幂等、首条消息并发建会话去重、消息稳定排序、Agent 调用 Token/耗时/状态落库、输入输出脱敏。
- 生成批次与图片的数据契约：批次类型与状态、`full` 必须引用 `sample`、图片角色 1 个 `main` + 5 个 `detail`、图片状态流转、历史可见性、替代图与尝试次数。
- 单桶前缀存储：`uploads/`、`generated/`、`thumbnails/`、`archive/`；UUID 对象名；上传图与生成图路径规则；缩略图最大宽 400px、WebP、质量 80；单文件 10MB；桶不公开，读取经后端鉴权。
- 5 年归档任务：扫描 `generated_images` 与 `uploaded_assets`，原件复制到 `archive/`、校验后删除原件、回写 `archived_at`；缩略图保持热存；失败记录重试且不阻塞其他记录；归档读取失败返回 `30014`。
- 一套中文日志的契约回归：表结构、约束、迁移回滚、种子幂等、超管初始化、路径规则、归档与读取降级。

### 1.2 不做

- 不做备份与恢复（属 11 号部署与运维 PRD）。
- 不做数据导出、导出 ZIP 的 24 小时清理（属 7 号 PRD）。
- 不做孤儿上传清理（10 号 §7.5）；本 demo 只交付归档任务。
- 不做 pg_trgm 与消息全文索引（10 号 §4.7 已明确本期不启用）。
- 不接 Redis：首条消息建会话与 `client_message_id` 去重改用数据库部分唯一索引 + 事务/咨询锁；正式实现再按 9 号接 Redis 幂等键。
- 不接 Celery / Celery Beat：归档任务提供手动触发命令与可注入时钟；每日 03:00 调度属 11 号。
- 不部署真实 MinIO：默认使用本地目录存储适配器，桶名与前缀路径与 MinIO 完全一致；正式实现切换后端不改路径契约。适配器保留 MinIO 后端开关，但不作为本 demo 验收项。
- 不实现模板、素材、尺寸的增删改查页面与接口；只建表、只种 10 号 §10.2 要求的尺寸预设。
- 不实现头像上传；`users.avatar_path` 恒为 `NULL`，`avatars/` 前缀保留。
- 不实现角色组合校验（超管 + 管理员、最多 2 个角色）的应用层逻辑；属 6 号 demo，本 demo 只验证数据库约束与种子矩阵。
- 不实现生成管线、Agent 编排、文字合成、失败重试、取消任务；属 2/4 号 demo。本 demo 只验证这些业务写入后数据层必须成立的约束。
- 不做分库分表、读写分离、多租户、数据仓库/ETL、业务数据物理删除、第三方冷存储。

### 1.3 相对 PRD 的最小化取舍

| PRD 要求 | 最小 demo 处理 | 原因 / 影响 |
| --- | --- | --- |
| MinIO 单桶 `esimage` | 本地目录适配器，根目录模拟桶、前缀路径完全一致 | 不引入 MinIO 服务；路径与归档语义可完整验证，正式实现换后端不改契约 |
| Celery Beat 每日 03:00 归档 | 手动触发命令 + 可注入时钟；调度表达式写入接口文档 | 调度属 11 号；任务本身可独立验证 |
| 固定 5 年热存 | `ARCHIVE_RETENTION_DAYS` 默认 1825，demo 可调小 | 不等待 5 年即可验证；正式实现固定 1825，配置化属后续需求 |
| Redis 60 秒幂等键 | 数据库部分唯一索引 + 事务/咨询锁 | 不引入 Redis；并发结果一致，正式实现可加 Redis 降低锁竞争 |
| Alembic 迁移 | 本 demo 保留 Alembic，因为迁移可回滚是 10 号核心验收项 | 与 2/4/6/8 号 demo 的「建表脚本」不同；本 demo 是数据底座，必须验证迁移 |
| 18 张业务表一次建齐 | 01~03 按身份/内容/配置三个域建表，每个切片带 schema 校验 | 表结构是 10 号的核心交付，不宜再裁剪；按域拆分便于单上下文实现 |
| 模板、素材、尺寸管理 | 只建表；只种 4 条尺寸预设 | 增删改查属 4 号；10 号 §10.2 只要求尺寸种子 |
| 超管权限落 `role_permissions` | 按 10 号 §10.2 为超管写入全部 23 条，运行时仍按角色绕过 | 与 6 号 demo「不落行、按角色即时授予」不同，差异记录在 §6 |
| 审计日志脱敏 | 提供共享脱敏函数与用例，覆盖密码、API Key、JWT | 10 号 §4.17/§12.8 要求；不实现完整审计页面 |
| 归档时的缩略图 | 缩略图不迁移，保持 `thumbnails/` 热存 | 10 号 §7.1/§13 已确定 |
| 备份恢复 | 不做 | 11 号已定义 `pg_dump`/`mc mirror` 与恢复演练，避免两处实现 |

## 2. 前置、环境与演示数据

### 2.1 前置

本目录是数据底座 demo，不依赖 1~9 号 demo 的页面或 HTTP 接口，可独立启动。需要：

| 前置 | 说明 |
| --- | --- |
| PostgreSQL 16 | 必须是 16；使用 `JSONB`、部分唯一索引、`CHECK` 约束与 `TIMESTAMPTZ` |
| Python 3.11+ | 运行迁移、种子、归档与契约回归；数据库驱动、迁移工具、图片处理库按实现选型 |
| 本地可写目录 | 模拟 `esimage` 桶的存储根目录；默认不要求 MinIO |
| 可选：MinIO | 仅当 `STORAGE_BACKEND=minio` 时使用；本 demo 不验收 |

> 不要求 Redis、Celery、Nginx、前端工程。若本机已有 1~9 号 demo 的数据库，请使用独立数据库名，避免迁移版本冲突。

### 2.2 演示数据与账号

- 本 demo 不创建 `demo_user` / `demo_admin` / `demo_dual`；这些账号由 1 号与 6 号 demo 维护。
- 首个超管由 `esimage-data init-super-admin` 创建，用户名与密码必须显式提供：
  - `INITIAL_SUPER_ADMIN_USERNAME`
  - `INITIAL_SUPER_ADMIN_PASSWORD`
- 本地演示可使用 `demo_super` / `Demo1234`，但必须在命令中显式传入，不得写成代码内默认值；部署到共享环境前必须改密。
- 种子数据只包含 10 号 §10.2 要求的项目，见 03 切片。

### 2.3 验证方式

- 迁移与 schema：`esimage-data db upgrade head`、`esimage-data db downgrade base`、`esimage-data db verify`。
- 种子与超管：`esimage-data seed`、`esimage-data init-super-admin`，重复执行验证幂等。
- 存储与归档：`esimage-data archive run --now <ISO8601>`，配合本地存储目录检查对象路径。
- 契约回归：`esimage-data verify --scope all`，逐条断言并输出中文日志（请求/操作、预期、实际、结论）；失败退出码非 0。

## 5. 验收总口径（演示脚本）

最小 demo 完成时，至少能完整演示以下路径：

1. 准备空数据库与空存储目录，执行迁移 → 18 张表全部建立；`db verify` 输出 18/18 与每张表的约束/索引检查结果。
2. 执行 `downgrade base` → 本 demo 创建的表与索引全部移除；再次 `upgrade head` → 重新建立且无残留冲突。
3. 连续执行两次 `seed` → 第二次不新增任何行；角色 3 条、权限点 23 条、超管角色权限 23 条、尺寸 4 条、提示词 8 条、提示词版本 8 条、启用模型配置 1 条。
4. 不传超管用户名或密码执行 `init-super-admin` → 命令失败并给出中文提示；传入显式密码 → 创建账号、密码为 bcrypt 哈希、授予 `super_admin`；再次执行不重置密码。
5. 用同一 `(session_id, client_message_id)` 写入两条消息 → 只落一条；并发用同一 `(user_id, client_message_id)` 创建首个会话 → 只创建一个会话。
6. 写入消息与 Agent 调用 → 消息按 `(created_at, id)` 稳定排序；`agent_runs` 的 `success` / `failed` / `skipped`、Token、耗时、摘要与错误信息正确；输入输出中的密码、API Key、JWT 已脱敏。
7. 创建 `full` 批次但不引用 `sample` → 被拒绝；引用后成功；示例批次图片角色固定 `main`；全套批次图片为 1 个 `main` + 5 个 `detail`；`success → generating` 等非法流转被拒绝；取消/替代图的历史可见性符合规则。
8. 上传 JPG/PNG/WEBP 合法图 → 元数据完整，原件落在 `uploads/{user_id}/{session_id}/{uuid}.{ext}`，缩略图落在规定 `thumbnails/` 路径且最大宽 400px、WebP、质量 80；GIF、超过 10MB、损坏图片、扩展名与 MIME 不符 → 被拒绝。
9. 不通过鉴权直接访问存储对象 → 不可读取；通过后端鉴权读取 → 成功；桶没有公开访问入口。
10. 将某张图和某张上传图的 `created_at` 设为超过保留期，执行 `archive run` → 原件复制到 `archive/` 后删除、`archived_at` 回写、数据库记录保留、缩略图仍在 `thumbnails/`；再次执行不重复归档。
11. 模拟归档复制失败 → 该记录不计成功、保留原状态，其他记录继续；修复后重试成功。
12. 读取已归档图片 → 从 `archive/` 返回；归档对象缺失 → 返回 `404 30014`，提示「文件归档中，请稍后重试」。
13. 执行 `verify --scope all` → 上述用例全部通过；每个用例输出中文日志，失败时指出「操作、预期、实际、结论」并返回非 0。

### 5.1 10 号 §12 验收标准覆盖情况

| 10 号 §12 | 本 demo 覆盖 | 说明 |
| --- | --- | --- |
| 1. 18 张表字段、类型、空值、默认值、约束一致 | 是 | Ticket 01 / 02 / 03；`db verify` 逐项检查 |
| 2. 外键不级联删除；账号软删除，历史保留 | 是 | Ticket 01 / 04 / 05；外键 `RESTRICT`，软删除用例 |
| 3. 用户名唯一约束包含已删除账号 | 是 | Ticket 01；`uq_users_username` 全量唯一 |
| 4. 角色组合规则在应用层生效 | 部分 | 数据库只保证关联表与种子矩阵；「最多 2 个角色、禁止超管 + 管理员」由 6 号 demo 验收 |
| 5. 批次类型与状态符合枚举；`full` 引用 `sample` | 是 | Ticket 05 |

## 6. 待确认项

> 以下事项在接口文档中给出了 demo 默认口径，正式实现前需要与 6/7/9/11 号文档统一；本 demo 不替任何一方做最终决定。

1. **超管权限是否落 `role_permissions`**：10 号 §10.2 要求「超管角色权限：全部权限点（用于展示）」，本 demo 写入 23 行；6 号 demo 约定不写行、运行时按角色即时授予全部权限。两者行为一致但数据不同，需统一。
2. **上传图缩略图路径**：10 号 §6.2 的缩略图模板包含 `batch_id`，但 `uploaded_assets` 没有批次概念。demo 约定上传图缩略图为 `thumbnails/{user_id}/{session_id}/{uuid}_thumb.webp`（无批次段），生成图仍为 `thumbnails/{user_id}/{session_id}/{batch_id}/{uuid}_thumb.webp`；需确认正式路径。
3. **归档保留期是否可配置**：10 号 §13 已确定固定 5 年、配置化后续再做；本 demo 用 `ARCHIVE_RETENTION_DAYS` 默认 1825，仅为缩短演示时间。
4. **归档调度实现**：10 号写每日 03:00，11 号写由 Celery Beat 调度；本 demo 只提供手动命令，需确认正式调度归属。
5. **归档复制成功但删除失败**：10 号未定义中间态。demo 约定重试时若 `archive/` 已存在且原件仍在，校验后删除原件；若原件已不存在且归档存在，直接回写 `archived_at`；需确认幂等规则。
6. **缩略图生成失败**：10 号要求生图成功、文字合成后由 Worker 同步生成缩略图，未定义失败时图片状态。demo 约定图片仍为 `success`、`thumbnail_path` 为空并记录任务日志；需确认是否应视为图片失败。
7. **初始超管密码策略**：10 号只要求「不得使用弱默认密码」，未给具体规则。demo 约定至少 8 位且同时包含字母与数字，并禁止 `admin` / `password` / `12345678` 等常见弱口令；需确认正式策略。
8. **审计动作码**：10 号只定义 `action` 字段，未给动作码清单；6 号 demo 使用 `account.*` / `role.update`，8 号 demo 使用 `model_config.update` / `prompt.update` / `prompt.rollback`；本 demo 不新增动作码，只验证脱敏。
9. **`updated_at` 自动更新方式**：10 号要求业务表带 `updated_at`、默认 `now()`，未说明由数据库触发器还是应用层维护。demo 由应用层写入；需确认是否统一加触发器。
10. **模板与素材是否进入 10 号种子**：10 号 §10.2 的种子清单不含模板与素材；4 号 demo 自行种入 2 条模板与 4 条素材。本 demo 只建表，不种模板/素材。
11. **管理员默认权限矩阵**：10 号 §11 只给权限点清单与超管专属项，未给管理员默认勾选。demo 按 6 号 §11「默认角色」列授予 13 个非超管权限，普通用户授予 4 个；需确认。
12. **已归档上传图是否仍可被批次引用**：10 号 §7.2 对 `uploaded_assets` 一视同仁地归档；若历史批次仍需要该参考图，读取时走 `archive/` 降级。demo 按此实现，需确认是否符合业务预期。
13. **`templates` / `material_assets` 被批次快照引用但无外键**：10 号 §3.1 明确无外键；本 demo 只建表，不校验引用完整性。
14. **导出与孤儿清理**：10 号 §7.4/§7.5/§9 不在本 demo 内；正式实现分别由 7 号与 10 号完整版承接。
15. **`source_sample_batch_id` / `source_image_id` 是否加外键**：10 号只声明为 BIGINT 字段，未写外键；demo 由应用层校验引用存在性与类型，需确认是否改为自引用外键。
16. **`client_request_id` 跨用户重复**：数据库唯一约束是全局的；同一用户重复提交返回原批次，不同用户提交相同值时应返回冲突还是忽略，10 号未定义。
17. **未绑定会话的上传图路径**：10 号 §6.2 的路径模板要求 `session_id`，但上传时可能尚未建会话。demo 用 `uploads/{user_id}/unbound/{uuid}.{ext}`，首次绑定只回填 `session_id`、不移动对象；需确认是否应移动到会话路径以严格匹配模板。
