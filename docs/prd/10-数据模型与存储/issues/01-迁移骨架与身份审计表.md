# 01: 迁移骨架与身份/审计表

**What to build:** 在一台本地 PostgreSQL 16 上，用 Alembic 建立可正向执行、可完整回滚的数据迁移基线，并按 10 号 PRD 建立 `users`、`roles`、`permissions`、`user_roles`、`role_permissions`、`audit_logs` 六张表。完成后，任何人执行迁移命令都能得到字段、空值、默认值、约束与索引完全一致的身份/审计数据层，并可用一条 schema 校验命令确认没有缺表、缺列、缺约束或缺索引。

**Blocked by:** 无（可立即开始）

**Status:** ready-for-agent

- [ ] 数据库连接通过 `DATABASE_URL` 配置，连接后校验 PostgreSQL 版本为 16、字符集为 UTF-8、会话时区为 Asia/Shanghai；不满足时命令失败并给出中文原因。
- [ ] Alembic 只有一个 head；`upgrade head` 建立六张表，`downgrade base` 按依赖逆序移除六张表及索引，再次 `upgrade head` 成功且无残留冲突。
- [ ] `users` 字段与 10 号 §4.1 一致：`username` 全局唯一且包含已删除账号、用户名格式 `^[A-Za-z0-9_]{4,20}$`、`status` 仅 `active`/`disabled`/`deleted`、`password_hash` 长度 255、`token_version` 默认 0、`deleted_at` 可空、审计时间齐全。
- [ ] `roles`、`permissions` 字段与 10 号 §4.2、§4.3 一致；`roles.code` 仅 `user`/`admin`/`super_admin`，`permissions.type` 仅 `menu`/`action`，两个 `code` 均唯一。
- [ ] `role_permissions`、`user_roles` 使用复合主键，外键均 `ON DELETE RESTRICT`；`user_roles` 建立 `idx_user_roles_role_id`。
- [ ] `audit_logs` 字段与 10 号 §4.17 一致；`result` 仅 `success`/`failed`；建立 `created_at`、`user_id + created_at`、`action + created_at`、`target_type + target_id` 四个索引；`detail` 为 JSONB 且允许为空。
- [ ] 所有索引与约束命名符合 10 号 §2：`idx_<table>_<columns>`、`uq_<table>_<columns>`、`ck_<table>_<...>`。
- [ ] 不建立任何级联删除；删除仍被引用的用户或角色时数据库拒绝。
- [ ] 提供 `esimage-data db verify`：逐表检查列、类型、空值、默认值、`CHECK`、唯一约束与索引，输出中文日志；任一项缺失时退出码非 0，并指出表、对象与差异。
- [ ] 本切片只交付迁移与 schema 校验，不写入角色、权限、账号或任何业务种子；种子在 03 切片完成。
- [ ] 迁移脚本可重复部署到空库与已有本 demo 旧版本的库；不得删除已有业务数据。
