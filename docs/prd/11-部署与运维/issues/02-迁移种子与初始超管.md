# 02: 迁移、种子与初始超管

**What to build:** 一个可重复执行的一次性 `migrate` 服务，使用与 backend 相同的镜像，先把数据库迁移到最新版本，再写入 10 号 §10.2 规定的全部种子，并创建唯一初始超管。迁移与种子失败时立即非 0 退出并输出可读的中文原因；重复执行不重复插入、不覆盖已被修改的数据；初始超管密码缺失或过弱时拒绝初始化。

**Blocked by:** 01 Compose 基线与依赖服务

**Status:** ready-for-agent

- [ ] `migrate` 不发布宿主机端口、不常驻、`restart: "no"`，退出码可被启动脚本与 Compose 判定。
- [ ] Alembic 正向迁移到 head，按 10 号创建 18 张业务表；字段类型、空值、默认值、约束、索引与外键与 10 号一致；`alembic current` 显示 head。
- [ ] 在一次性临时数据库上验证 `downgrade -1` 可回滚、随后 `upgrade head` 可再次成功；迁移脚本不删除业务数据。
- [ ] 种子包含：3 个内置角色、10 号第 11 章全部权限点、`super_admin` 角色的权限展示行、四个平台 1000×1000 尺寸预设、8 个 Agent 初始系统提示词与 `platform_rule` 初始规则、一条 `api_key` 为空的默认模型配置。
- [ ] 种子脚本幂等：第二次执行不新增重复行；已存在且被人工修改的数据不被覆盖；脚本输出每个种子项的「新增 / 跳过」中文日志。
- [ ] 初始超管从 `ADMIN_INITIAL_USERNAME`、`ADMIN_INITIAL_PASSWORD` 读取；用户名满足 10 号 `^[A-Za-z0-9_]{4,20}$`；创建时绑定 `super_admin` 角色、`status=active`、`token_version=0`，密码以 bcrypt 存储。
- [ ] 密码缺失、长度不足 12、少于 3 类字符或与用户名相同时，`migrate` 非 0 退出，提示明确说明缺失项或强度要求。
- [ ] 初始超管已存在时跳过创建，不重置已有密码，不改变角色与状态；日志明确提示「已存在，跳过」。
- [ ] `migrate` 仅在依赖服务健康后执行；应用服务在迁移完成后启动，符合 11 号 §8.1 的首次部署顺序。
- [ ] 若 1 号 demo 的登录接口已落地，用初始超管调用登录成功；否则用数据库查询与 bcrypt 校验证明账号可用，并在验收日志中说明登录闭环由 1 号 demo 覆盖。
