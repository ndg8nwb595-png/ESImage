# 06: 备份与恢复

**What to build:** 由宿主机 cron 在每日 02:00 备份 PostgreSQL、02:30 备份 MinIO，备份写入独立的 `backup` 卷；文件按 `esimage_db_{yyyyMMdd}.dump` 与 `esimage_minio_{yyyyMMdd}/` 命名，保留 7 天；备份完成后校验文件存在、非空且数据库转储可读。提供恢复脚本，在一次性的 demo 栈上完成一次「备份 → 破坏数据 → 恢复 → 复验」演练。

**Blocked by:** 02 迁移、种子与初始超管；03 应用镜像与双健康探针

**Status:** ready-for-agent

- [ ] 宿主机 cron 配置包含每日 02:00 数据库备份、02:30 MinIO 备份与每日日志轮转；备份不依赖应用容器生命周期，应用停止时仍可由宿主机触发。
- [ ] 数据库备份使用 `pg_dump -Fc`，输出 `esimage_db_{yyyyMMdd}.dump` 到 `backup` 卷；完成后校验文件存在、大小大于 0，且 `pg_restore -l` 能列出内容。
- [ ] MinIO 备份使用 `mc mirror`，输出到 `esimage_minio_{yyyyMMdd}/`；完成后校验目录存在且对象数大于 0。
- [ ] 两类备份均按 `BACKUP_RETAIN_DAYS`（默认 7）清理过期文件；只删除匹配命名规则的本系统备份，不影响目录内其他文件。
- [ ] 备份脚本输出中文日志：开始时间、结束时间、文件路径、大小、校验结果、耗时、成功/失败；失败时返回非 0 退出码，不静默吞错。
- [ ] 备份脚本重跑幂等：同一天重复执行不产生半成品；失败后可直接重跑，成功结果可覆盖同名备份。
- [ ] 备份日志与备份文件不包含数据库密码、MinIO 密钥或 JWT；备份目录权限仅部署账号可读写，备份文件不进入 Git。
- [ ] 恢复脚本接受数据库转储与 MinIO 备份目录作为参数，必须显式确认才执行；未确认时退出且不改动任何数据。
- [ ] 恢复流程：停止 backend、worker、beat；恢复 PostgreSQL；恢复 MinIO；启动服务；调用两个健康接口并检查关键种子数据。
- [ ] 在一次性 demo 栈上完成演练：先执行两类备份，再删除一条尺寸预设与一个 MinIO 对象，执行恢复后数据与对象恢复，`/api/health` 与 `/api/v1/health` 均返回 200。
- [ ] 恢复脚本输出中文步骤日志与最终摘要（恢复耗时、数据库对象数、MinIO 对象数、健康结果），失败时返回非 0。
- [ ] 文档明确：生产恢复前先再次备份；`pg_restore --clean --if-exists` 只用于可丢弃的 demo 栈；备份复制到远端与加密传输不在本切片内。
