# 08: 一键启动与验收脚本

**What to build:** 在干净机器上，一条命令完成镜像构建、依赖启动、健康等待、迁移、应用启动与健康确认；另一条命令逐项执行本目录全部验收用例，用中文日志输出请求、预期、实际与结论，任一失败立即非 0 退出并保留现场；停止命令默认只停容器、不删卷。

**Blocked by:** 04 Nginx 网关与 SSE 代理；05 结构化日志与 request_id；06 备份与恢复；07 Worker/Beat 基线

**Status:** ready-for-agent

- [ ] `demo_up.sh` 检查前置：Docker、Compose v2、80 端口空闲、`.env` 存在且必填变量非空；任一不满足时输出中文原因并非 0 退出。
- [ ] `demo_up.sh` 依次执行构建、启动依赖、等待三项健康、执行迁移、启动应用服务、等待 backend/frontend/nginx 健康；任一步失败即停止后续步骤并保留日志。
- [ ] `demo_up.sh` 可重复执行：已存在的容器与卷不重复创建，迁移幂等，种子不重复插入。
- [ ] `demo_down.sh` 默认只停止容器，保留全部命名卷；帮助信息明确警告生产禁止 `docker compose down -v`；只有显式清理参数才删除卷。
- [ ] `demo_verify.sh` 覆盖：Compose 配置与端口暴露、三依赖健康、桶与前缀、迁移幂等、弱密码拒绝、双健康接口、降级与恢复、网关静态与 API、`/api/docs` 内网限制、10MB 通过与超限 413、SSE 增量输出、日志 JSON 与轮转、`request_id` 关联、备份命名/校验/保留、恢复演练、Worker ping、Beat 时区、`ops.selftest`。
- [ ] 每个验收用例输出中文日志：用例名、请求/操作、预期结果、实际结果、结论；失败时同时输出可定位的命令与日志片段。
- [ ] 任一用例失败立即以非 0 退出，不继续执行后续用例；全部通过时输出汇总与总耗时并以 0 退出。
- [ ] 验收脚本不依赖人工点击或手工改库；所需测试数据由脚本自行准备与清理，不污染种子数据。
- [ ] 验收脚本验证「停止 Redis → 两个健康接口 503 → 恢复 Redis → 200」，并验证依赖恢复不要求重启 backend。
- [ ] 验收脚本验证「删除一条种子数据与一个 MinIO 对象 → 备份 → 恢复 → 数据与对象恢复」，恢复只在可丢弃的 demo 栈执行。
- [ ] 验收脚本结束时打印访问地址、初始超管用户名来源、日志与备份目录位置，以及下一步（首次登录改密）说明。
- [ ] 交付 `README` 快速开始段落所需的操作顺序与预期输出，与脚本行为一致。
