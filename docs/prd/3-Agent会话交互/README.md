## 1. 最小 demo 范围

### 1.1 做

- 会话重命名：当前会话可重命名，去除首尾空格后 1~50 字符，纯空格拒绝；重命名后自动命名不再覆盖。
- 会话软删除：二次确认文案与 PRD 一致；`status` 置为 `hidden`；用户列表立即隐藏；删除当前会话后自动切换到最近活跃会话，没有则进入空会话草稿；用户端不提供恢复入口。
- 会话切换：切换后加载该会话的消息分页、需求摘要与最近批次；后台生成任务继续执行，结果区只展示当前会话的任务。
- 消息展示：用户文本、Agent 文本、系统通知三种消息；用户消息保留换行、不解析 Markdown；Agent 消息支持基础 Markdown 白名单，禁止原始 HTML；链接只允许 `http/https` 且新窗口打开；Agent 消息显示「规划 Agent」「商品理解 Agent」标签。
- 消息状态：发送中、流式接收中、已完成、失败可重试；前端中止请求时展示「已停止生成」。
- 输入规则：商品名称未填时输入框禁用；去除首尾空格后 1~2000 字符；Enter 发送、Shift + Enter 换行；回复中发送按钮禁用；聊天区不支持上传或粘贴图片。
- 轻链路：每条消息只调用规划 Agent 与商品理解 Agent，按固定顺序输出 `agent_status`；聊天不创建生成批次、不触发生图。
- 需求摘要：每轮聊天后由商品理解 Agent 更新 `requirement_summary`，并在 `done` 事件返回；摘要字段至少覆盖商品名称、推断类目、卖点、目标人群、场景偏好、文案语气、用户限制。
- 上下文窗口：每次轻链路调用携带系统提示词、当前参数、需求摘要、最近 10 轮对话、已确认示例图描述（若有）；超过 10 轮从最早一轮丢弃，并注入一条不落库的省略说明；不同会话之间不共享上下文。
- Agent 调用明细：每次回复在 `agent_runs` 落库两条记录（规划、商品理解），包含状态、Token、耗时与错误信息；演示桩 Token 为 0。
- 需求变化提示：已确认示例后，聊天改变风格、卖点或尺寸时，`done` 事件返回 `requirement_changed=true`，前端展示「需求已变化，建议重新生成示例图」；聊天本身不创建批次。
- 基础权限：仅普通用户可用；只能访问自己的会话与消息；未登录返回 401，越权返回 403/404。

### 1.2 不做

- 显式创建会话接口 `POST /sessions`（前端仍由首条消息或生成时后端原子创建）。
- 会话恢复、回收站、用户端查看已隐藏会话。
- 聊天记录导出、分享会话、多人群聊、跨会话记忆。
- 语音输入、聊天区图片上传与图片粘贴。
- 聊天中直接触发生图。
- 后端「取消生成」接口；消息的「已取消」只作为前端中止请求后的本地展示状态。
- 管理后台聊天记录页面、消息搜索、Agent 调用明细查询接口（8 号 PRD）。
- 真实内容审核；`30007` 保留但不触发。
- 真实 Token 计费；未接真实模型时 Token 固定为 0。
- 模型上下文 Token 上限的二次压缩（先丢历史、再压缩需求摘要）；最小 demo 只做 10 轮截断。
- 5 年热存与归档、操作审计的完整实现。
- 手机端适配。

### 1.3 相对 PRD 的最小化取舍

| PRD 要求 | 最小 demo 处理 | 原因 / 影响 |
| --- | --- | --- |
| Redis 短期幂等键（TTL 60 秒） | 进程内锁 + 数据库唯一约束去重 `(user_id, client_message_id)`；单实例部署 | 降低本地启动成本；正式实现换 Redis，接口与幂等语义不变 |
| 规划 / 商品理解调用真实文本模型 | 未配置 `text_model` 时使用确定性演示桩，按同一事件顺序输出固定回复与最小需求摘要；配置后可接真实模型 | 保证对话可演示；接口、落库字段与 SSE 事件不变 |
| 上下文 Token 上限与摘要压缩 | 只实现最近 10 轮截断与省略说明；`max_context_tokens` 预留配置，不做二次压缩 | 演示桩不受 Token 上限约束；正式实现补二次压缩 |
| 内容审核 | 不调用审核；`30007` 仅保留错误码 | 避免引入审核服务；正式实现补 |
| Token 统计 | 演示桩写入 0；真实模型按返回值写入 | 不影响字段与展示；正式实现补计费口径 |
| 消息「已取消」 | 不新增后端状态；前端中止请求后本地展示「已停止生成」，刷新后按已落库状态展示 | `chat_messages.status` 只有 `sending/done/failed`；避免新增枚举 |
| 系统通知由生成流程产生 | 本目录只实现系统通知的展示；示例图完成、任务失败等通知由 2 号/4 号生成流程写入 | 3 号 PRD 未定义生成侧通知接口；最小 demo 用种子消息验证渲染 |
| 管理后台可追溯隐藏会话 | 只保证数据库保留 `status=hidden` 与消息；不提供管理端页面 | 管理端属于 8 号 PRD |
| 需求变化判定 | 后端按「风格 / 卖点 / 尺寸」做字段级比对；不做语义级比对 | PRD 未列出精确字段；字段级比对可解释、可测试 |
| 已确认示例图描述进入上下文 | 用已确认示例批次的商品名称、风格与需求摘要快照拼成描述；不新增摘要字段 | 10 号数据模型没有「示例图描述」字段 |
| 聊天中的参数 | 复用 2 号 demo 的 `params` 请求字段与 localStorage；不新增会话参数持久化 | 3 号 PRD 明确会话不持久化参数面板内容 |

## 5. 验收总口径（演示脚本）

最小 demo 完成时，至少能完整演示以下路径：

1. `demo_user` 登录并进入 `/workspace`；商品名称未填时聊天输入框禁用，填写后可用。
2. 发送第一条消息 → 用户气泡立即上屏 → 依次出现「规划 Agent」「商品理解 Agent」状态 → 回复逐字流式展示 → 会话自动命名并出现在左侧列表。
3. 未填写风格时，回复列出 3~5 个风格建议；用户用自然语言选择后，下一轮回复按新风格理解需求。
4. 打开当前会话菜单 → 重命名为纯空格或超过 50 字符被拒绝；输入合法名称后列表与标题立即更新，刷新后仍保留。
5. 删除当前会话 → 出现二次确认文案 → 确认后列表隐藏该会话并自动切换到最近活跃会话；没有其他会话时回到空会话草稿；数据库中该会话 `status=hidden`，消息仍保留。
6. 连续发送超过 10 轮 → 第 11 轮起只携带最近 10 轮；省略说明只出现在本次上下文，不出现在消息列表与 `chat_messages`。
7. 回复过程中断网 → 出现「连接中断，正在重试」→ 自动重试最多 2 次且复用同一 `client_message_id` → 消息不重复；仍失败则标记失败，点击重试不重复计费。
8. 输入框验证：空消息、超过 2000 字符阻止发送；Enter 发送、Shift + Enter 换行；回复中发送按钮禁用；粘贴图片被拦截并提示「请在右侧商品图区域上传图片」。
9. Agent 回复中的加粗、列表、行内代码正常渲染；原始 HTML 以文本显示；`http/https` 链接新窗口打开。
10. 示例图确认后，在聊天中改变风格或卖点 → 出现「需求已变化，建议重新生成示例图」→ 点击「重新生成示例」后提示消失，已生成的全套正式图不受影响。
11. 全程检查 `generation_batches`：聊天不新增任何批次。
12. 未登录访问接口返回 401；`demo_admin` 调用聊天接口返回 403；访问他人会话返回 404，不泄露数据。

## 6. 待确认项

以下事项在接口文档中给出了 demo 默认口径，正式实现前需要与 9 号、10 号文档统一：

1. **已隐藏会话的 PATCH / DELETE 语义**：PRD 只说明用户端不展示、后台可查；demo 对已隐藏或不属于当前用户的会话统一返回 404 `30013`，正式实现需确认是否允许幂等删除返回 200。
2. **重复消息的返回形式**：PRD 7.4 要求「已存在且已完成：直接返回已保存消息」，未定义在 SSE 下如何返回；demo 约定 `meta.duplicate=true` + 一次完整 `delta` + `done` 重放，正式实现需与 9 号统一。
3. **需求变化的比对字段**：PRD 只写「风格 / 卖点 / 尺寸」；demo 约定比对 `style_text`、`selling_points`、`width/height` 三类字段，正式实现需确认是否包含目标人群、场景等。
4. **已确认示例图描述**：PRD 8.1 要求把「已确认示例图的描述」加入上下文，10 号没有对应字段；demo 用商品名称、风格与需求摘要快照拼接，正式实现需确认是否新增字段或由提示词构建器生成。
5. **系统通知的写入方**：3 号 PRD 只定义展示规则，未定义系统通知由谁写入；demo 只实现渲染，由 2 号/4 号的生成流程写入，正式实现需统一。
6. **「需求已变化」提示的消失时机**：PRD 未定义；demo 约定用户重新生成示例或手动关闭后消失，正式实现需产品确认。
7. **消息中止状态**：`chat_messages.status` 没有 `cancelled`；demo 只在前端本地展示「已停止生成」，刷新后按落库状态展示，正式实现需确认是否新增状态。
8. **真实模型接入后的 Token 上限与摘要压缩**：demo 只做 10 轮截断，正式实现按模型配置补二次压缩。
