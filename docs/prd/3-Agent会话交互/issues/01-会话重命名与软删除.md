# 01: 会话重命名、软删除与切换闭环

**What to build:** 用户可以在左侧会话列表中对当前会话重命名和软删除。重命名去除首尾空格后必须为 1~50 个字符，纯空格或超长时提示并聚焦输入框，不发送请求；成功后列表标题、聊天区标题与刷新后的状态一致，自动命名不再覆盖用户标题。删除必须出现与 PRD 一致的二次确认，确认后会话从用户列表隐藏、消息仍保留，若删除的是当前会话则自动切换到最近活跃会话，没有其他会话时回到空会话草稿；用户端不提供恢复入口。切换会话时加载该会话的消息分页、需求摘要与最近批次，后台生成任务继续执行，但结果只展示在当前会话下。

**Blocked by:** 2 号 demo 04（会话列表与聊天轻链路）

**Status:** ready-for-agent

- [ ] 当前会话的菜单提供「重命名」与「删除会话」两个操作；其他会话项不提供重命名入口。
- [ ] 重命名弹窗预填当前标题；去除首尾空格后为空或纯空格时提示「请输入会话名称」并聚焦输入框，不发送请求。
- [ ] 去除首尾空格后超过 50 个字符时提示「会话名称不能超过 50 个字符」并聚焦输入框，不发送请求。
- [ ] 合法标题保存后，会话列表标题、聊天区标题立即更新；刷新页面后仍为修改后的标题。
- [ ] 用户重命名后，后续消息或生成不再自动覆盖标题；未重命名时仍按 2 号 demo 04 的自动命名规则执行。
- [ ] 点击「删除会话」出现二次确认，文案为「删除后该会话将从你的列表隐藏，管理员仍可追溯，是否继续？」；取消时不做任何修改。
- [ ] 确认删除后会话 `status` 置为 `hidden`，会话列表不再展示；数据库中的消息与生成记录保留。
- [ ] 删除的是当前会话时，自动切换到按 `last_message_at` 排序的最近一个活跃会话；没有活跃会话时进入空会话草稿并清空聊天区与结果区。
- [ ] 用户端不提供恢复入口；刷新后不会重新出现已删除会话。
- [ ] 只能重命名或删除当前用户的 `active` 会话；他人会话、已隐藏会话返回 404 `30013`，不泄露存在性。
- [ ] 未登录返回 401；缺少 `user.workspace` 返回 403 `20005`；管理员账号不能调用用户端会话操作。
- [ ] 切换会话后加载该会话的消息分页、需求摘要与最近批次；其他会话正在生成的批次继续执行，结果区不展示非当前会话的任务。
- [ ] 会话列表仍按 `last_message_at` 倒序，展示标题、最多 30 字的最后消息摘要与时间，当前会话高亮。
- [ ] 不新增 `POST /sessions`、恢复会话或回收站相关接口。
- [ ] 后端 pytest、前端 vitest 覆盖重命名、软删除、删除后切换与越权场景；每个测试步骤输出中文日志。
