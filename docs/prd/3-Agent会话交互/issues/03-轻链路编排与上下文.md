# 03: 轻链路编排、上下文窗口与调用明细

**What to build:** 每条聊天消息只走轻链路：先规划 Agent 判断意图并决定追问策略，再商品理解 Agent 提取商品画像、更新会话的需求摘要。SSE 按固定顺序推送两个 Agent 的开始与结束状态和增量文本，`done` 事件返回最新需求摘要；未填写风格时回复给出 3~5 个风格建议。每次调用携带系统提示词、当前参数、需求摘要、最近 10 轮对话与已确认示例图描述，超过 10 轮丢弃最早轮次且省略说明不落库。两个 Agent 的调用记录与 Token、耗时写入 `agent_runs`，聊天全程不创建生成批次。

**Blocked by:** 2 号 demo 04（会话列表与聊天轻链路）

**Status:** ready-for-agent

- [ ] 每条消息的 `agent_status` 顺序固定为：`planner` started → `planner` finished → `product_understanding` started → `product_understanding` finished；`delta` 只出现在商品理解 Agent 开始之后，`ping` 可穿插在任意位置。
- [ ] 除 `planner` 与 `product_understanding` 外，不出现文案、提示词、生图、质量审核、修复、平台规范等 Agent 的状态。
- [ ] 聊天请求不创建 `generation_batches`，不创建 `generated_images`，不修改已有批次；测试用例在发送前后比对表内数量。
- [ ] 规划 Agent 能区分补充需求、修改风格、询问建议、闲聊四类意图，并输出下一轮对话策略；不展示完整思维链，只展示阶段状态。
- [ ] 回复最多追问 1~2 个问题，同一条回复不出现连环追问；建议必须可执行，不承诺无法实现的效果。
- [ ] 用户未填写风格时，回复列出 3~5 个适合该商品的风格建议；用户用自然语言选择后，下一轮按所选风格理解需求。
- [ ] 商品理解 Agent 每轮更新会话的 `requirement_summary`，字段至少包含商品名称、推断类目、卖点列表、目标人群、场景偏好、文案语气与用户明确提出的限制。
- [ ] `requirement_summary` 持久化到会话并在 `done` 事件返回；刷新或切换会话后，后端仍以最新摘要作为下一轮上下文。
- [ ] 每次轻链路调用的上下文由五部分组成：Agent 系统提示词、前端随请求提交的当前参数、`requirement_summary`、最近 10 轮对话、已确认示例图描述（若有）。
- [ ] 对话超过 10 轮时，从最早一轮开始丢弃；注入一条「更早的对话已省略，需求摘要以当前 `requirement_summary` 为准」的省略说明，该说明只用于本次模型请求，不写入 `chat_messages`、不出现在消息分页中。
- [ ] 不同会话之间不共享上下文；新建会话从空上下文开始，切换会话只加载对应会话的消息与摘要。
- [ ] 参数面板提交的商品名称、风格、宽高优先于需求摘要中的同名字段。
- [ ] 每次回复在 `agent_runs` 写入两条记录，分别对应 `planner` 与 `product_understanding`，包含状态、模型名、输入/输出摘要、Token、耗时与错误信息；演示桩 Token 写 0，真实模型按返回值写入。
- [ ] Agent 回复消息的 `token_in` / `token_out` 在 `done` 前更新；`done` 返回 `message_id`、`token_in`、`token_out`、`requirement_summary` 与 `requirement_changed`；没有已确认示例时 `requirement_changed=false`。
- [ ] 模型调用失败时通过 SSE `error` 返回 30001，Agent 消息标记 `failed`，用户消息保留；用户可用同一 `client_message_id` 重试。
- [ ] 未配置 `text_model` 时使用确定性演示桩，事件顺序、落库字段与真实模型一致；配置后可直接切换到真实模型，接口与 SSE 契约不变。
- [ ] 后端 pytest 覆盖两个 Agent 的调用顺序、10 轮截断、摘要落库、`agent_runs` 两条记录与聊天不建批次；每个测试步骤输出中文日志。
