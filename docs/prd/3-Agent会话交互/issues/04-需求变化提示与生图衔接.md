# 04: 需求变化提示与生图衔接

**What to build:** 示例图已被确认后，用户继续在聊天中改变风格、卖点或尺寸时，后端在 `done` 事件标记需求已变化，聊天区出现「需求已变化，建议重新生成示例图」提示。聊天只更新需求摘要，不创建或修改生成批次；用户点击「重新生成示例」时沿用 2 号 demo 的示例生成流程，使用最新需求摘要与当前参数，已生成的全套正式图保持不变。

**Blocked by:** 03（轻链路编排、上下文窗口与调用明细）、2 号 demo 06（确认并生成全套与结果网格）

**Status:** ready-for-agent

- [ ] 后端以当前会话最近一个已确认示例批次的参数快照与需求摘要快照为基准，比对最新聊天参数与最新 `requirement_summary` 中的风格、卖点与尺寸。
- [ ] 风格（`style_text`）、卖点列表或宽高任一发生变化时，`done` 事件返回 `requirement_changed=true`；未变化时返回 `false`。
- [ ] 会话没有已确认示例批次时，`requirement_changed` 始终为 `false`。
- [ ] 前端在收到 `requirement_changed=true` 后展示「需求已变化，建议重新生成示例图」提示；提示不阻塞继续聊天，也不自动触发生成。
- [ ] 提示在用户点击「重新生成示例」后消失；用户也可以手动关闭提示。刷新或切换会话后不要求保留提示，下一次聊天完成时重新判定。
- [ ] 聊天过程中不创建 `sample` / `full` 批次，不修改批次状态、参数快照、需求摘要快照或图片；测试用例在聊天前后比对相关表。
- [ ] 点击「重新生成示例」沿用 2 号 demo 05 的流程，提交当前参数与最新 `requirement_summary`；新批次创建成功后，旧示例批次与已确认的全套批次均保留。
- [ ] 已确认示例对应的全套正式图不因后续聊天或重新生成示例而改变；不提供在全套结果上局部修改的入口。
- [ ] 生成示例图时提交的需求摘要进入批次快照，后续聊天修改摘要不回溯修改已创建批次。
- [ ] 不新增「需求变化」查询接口；判定结果只通过聊天 SSE 的 `done` 事件返回。
- [ ] 后端 pytest 覆盖三种变化（风格、卖点、尺寸）、无变化、无已确认示例与聊天不建批次；每个测试步骤输出中文日志。
