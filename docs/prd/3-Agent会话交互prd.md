## 1. 文档目的与范围

### 1.1 目的

定义用户与 Agent 之间的会话：会话如何创建、命名、切换、软删除；消息如何展示；聊天走哪条 Agent 链路；SSE 如何传输；上下文如何截断；聊天与生图如何衔接。

### 1.2 本期范围

- 会话列表、新建、重命名、软删除。
- 消息类型与展示。
- 聊天输入框规则。
- 聊天轻链路（规划 + 商品理解）。
- SSE 流式协议。
- 上下文窗口策略。
- 需求摘要与生图请求的衔接。
- 异常、重连与消息幂等。

### 1.3 不做

- 多人群聊、分享会话。
- 聊天记录导出。
- 语音输入、图片粘贴进聊天。
- 聊天中直接触发生图。
- 跨会话记忆。

## 2. 会话模型

### 2.1 定义

一个「会话」对应一个商品项目的创作上下文，数据库对应 `creative_sessions`。

- 一个会话可包含多次生成（示例批次与全套批次）。
- 会话内共享：聊天消息、参数快照、需求摘要、上传图、生成记录。
- 不同会话之间上下文隔离。

### 2.2 创建时机

会话在以下任一时刻创建：

1. 用户在当前工作台发送第一条聊天消息。
2. 用户点击「生成示例图」（若尚未有会话）。

工作台初始为空会话草稿状态，不提前写入数据库。

- 上述两种动作都由后端在事务内原子创建会话，并同时写入首条消息或生成批次；前端不需要先调用 `POST /sessions`。
- 首条消息以 `client_message_id` 做幂等；并发重复请求返回同一会话，不重复创建。

### 2.3 会话字段

| 字段 | 说明 |
| --- | --- |
| id | 会话 ID |
| user_id | 所属用户 |
| title | 会话标题 |
| status | `active` / `hidden` |
| requirement_summary | 需求摘要（JSON），由商品理解 Agent 维护 |
| last_message_at | 最后一条消息时间 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

> 会话不持久化参数面板内容；参数与上传图 ID 由前端 localStorage 保存，换设备或清缓存会丢失。

### 2.4 自动命名

- 首条用户消息存在时：取消息前 20 个字符作为标题。
- 首条动作是生成时：取商品名称作为标题。
- 都不可用时：标题为「未命名会话」。
- 自动命名只在标题为空时执行一次；用户重命名后不再自动覆盖。

## 3. 会话列表与操作

### 3.1 列表

- 位于页面最左侧独立栏，与聊天框、参数面板并列。
- 按 `last_message_at` 倒序排列。
- 只展示当前用户 `status=active` 的会话。
- 每项展示：标题、最后一条消息摘要（最多 30 字）、时间。
- 当前会话高亮。

### 3.2 新建会话

1. 点击「新建会话」。
2. 清空当前聊天区与结果区，进入空会话草稿状态。
3. 不立即写入数据库；发送第一条消息或生成时由后端事务内原子创建。
4. 若当前会话没有任何消息与生成，允许直接切换，不产生空会话。

### 3.3 重命名

- 支持对当前会话重命名。
- 长度 1~50 个字符，去除首尾空格。
- 不允许纯空格。
- 重命名不影响消息与生成记录。

### 3.4 软删除

1. 用户点击会话菜单中的「删除会话」。
2. 二次确认：「删除后该会话将从你的列表隐藏，管理员仍可追溯，是否继续？」
3. 后端将会话 `status` 置为 `hidden`。
4. 用户列表不再展示；若删除的是当前会话，自动切换到最近一个活跃会话或空状态。
5. 管理员后台仍可查看该会话的聊天与生图记录。
6. 用户端不提供恢复入口。

### 3.5 切换会话

- 点击列表中的会话，加载该会话的消息、参数快照、最近生成结果。
- 切换时若有正在生成的批次，允许切换，但结果区只展示当前会话的任务；后台任务继续执行。

## 4. 消息类型与展示

### 4.1 消息类型

| 类型 | 发送方 | 展示 |
| --- | --- | --- |
| 用户文本 | 用户 | 右侧气泡，保留换行 |
| Agent 文本 | 轻链路 Agent | 左侧气泡，支持基础 Markdown |
| 系统通知 | 系统 | 居中灰底提示，如「示例图已生成」「任务失败」 |
| 上传通知 | 系统 | 左侧卡片，展示本次上传的商品图缩略图 |

### 4.2 消息字段

| 字段 | 说明 |
| --- | --- |
| id | 消息 ID |
| session_id | 所属会话 |
| role | `user` / `assistant` / `system` |
| agent_code | Agent 消息所属 Agent（轻链路为 `planner` 或 `product_understanding`） |
| content | 消息正文 |
| content_type | `text` / `markdown` |
| token_in / token_out | 本条消息关联的 Token 消耗（Agent 消息） |
| created_at | 创建时间 |

### 4.3 渲染规则

- 用户消息保留换行，不解析 Markdown。
- Agent 消息支持基础 Markdown：加粗、斜体、有序/无序列表、换行、行内代码。
- 禁止渲染原始 HTML，防止 XSS。
- 链接仅允许 `http/https`，点击后新窗口打开。
- 消息时间按本地时区展示，悬停显示完整时间。
- Agent 消息显示 Agent 名称标签，如「规划 Agent」「商品理解 Agent」。

### 4.4 消息状态

| 状态 | 展示 |
| --- | --- |
| 发送中 | 用户气泡右侧 loading |
| 已发送 | 正常显示 |
| 流式接收中 | 左侧气泡逐字追加，末尾光标闪烁 |
| 已完成 | 正常显示 |
| 失败 | 气泡下方显示「发送失败，点击重试」 |
| 已取消 | 显示「已停止生成」 |

## 5. 输入框与发送规则

### 5.1 可用条件

- 商品名称填写后，输入框即可用；风格、尺寸、商品图、模板均为选填。
- 商品名称未填写时输入框禁用，占位文案「请先填写商品名称后再开始对话」。
- 后端同样校验；商品名称为空的聊天请求返回参数错误。

### 5.2 输入规则

| 项目 | 规则 |
| --- | --- |
| 最大长度 | 2000 个字符 |
| 发送快捷键 | Enter 发送；Shift + Enter 换行 |
| 空消息 | 禁止发送（去除首尾空格后为空） |
| 发送中 | 当前回复未结束时，发送按钮禁用，避免并发请求 |
| 图片 | 聊天区不支持上传图片；提示用户使用右侧商品图上传 |
| 粘贴图片 | 拦截并提示「请在右侧商品图区域上传图片」 |

### 5.3 发送流程

1. 用户输入消息并发送。
2. 前端生成 `client_message_id`（UUID），用于幂等。
3. 用户消息立即上屏，状态为「发送中」。
4. 调用聊天接口，建立 SSE 连接。
5. 后端保存用户消息，调用轻链路 Agent。
6. 流式返回 Agent 回复。
7. 完成后更新消息状态与 Token。

## 6. 聊天轻链路

### 6.1 调用范围

每条聊天消息只调用：

1. 规划 Agent
2. 商品理解 Agent

不调用文案、提示词、生图执行、质量审核、修复、平台规范 Agent。

### 6.2 职责

| Agent | 在聊天中的职责 |
| --- | --- |
| 规划 Agent | 判断用户意图（补充需求/修改风格/询问建议/闲聊），决定是否需要追问，输出下一轮对话策略 |
| 商品理解 Agent | 从商品名称、上传图、对话中提取商品画像与需求摘要，更新 `requirement_summary` |

### 6.3 输出

Agent 回复应包含：

- 对用户需求的理解确认。
- 缺失信息的追问（最多 1~2 个问题，避免连环追问）。
- 可执行的建议（如「建议选择生活场景风格」）。
- 若用户未填写风格，规划 Agent 应列出 3~5 个适合该商品的风格建议，等待用户用自然语言选择或自行补充。
- 不直接生成图片，不承诺无法实现的效果。

### 6.4 需求摘要

- `requirement_summary` 为 JSON，至少包含：
  - 商品名称
  - 推断类目
  - 卖点列表
  - 目标人群
  - 场景偏好
  - 文案语气
  - 用户明确提出的限制
- 每次聊天后由商品理解 Agent 更新。
- 生成示例图时随参数一起提交给全链路。
- 用户修改参数面板时，参数面板的值优先于摘要中的同名字段。

## 7. SSE 协议

### 7.1 连接

```http
POST /api/v1/sessions/{session_id}/messages
Authorization: Bearer <token>
Content-Type: application/json
Accept: text/event-stream

{
  "client_message_id": "uuid",
  "content": "用户输入"
}
```

- 使用 `fetch` + `ReadableStream` 读取，便于携带 `Authorization`。
- 响应头：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
- Nginx 必须关闭该路径的缓冲。

### 7.2 事件类型

| event | data 示例 | 说明 |
| --- | --- | --- |
| `meta` | `{"message_id": 1001, "session_id": 12}` | 连接建立，返回服务端消息 ID |
| `agent_status` | `{"agent_code": "planner", "status": "started"}` | Agent 开始/结束/跳过 |
| `delta` | `{"content": "好的，"}` | 增量文本 |
| `done` | `{"message_id": 1001, "token_in": 120, "token_out": 300, "requirement_summary": {...}}` | 完成 |
| `error` | `{"code": 30001, "message": "模型调用失败"}` | 错误 |
| `ping` | `{}` | 心跳，每 15 秒 |

### 7.3 事件顺序

```
meta
agent_status(planner, started)
agent_status(planner, finished)
agent_status(product_understanding, started)
delta...
agent_status(product_understanding, finished)
done
```

- 心跳可穿插在任意位置。
- `done` 或 `error` 之后服务端关闭连接。

### 7.4 幂等

- 前端每次发送生成 `client_message_id`。
- 后端以 `(session_id, client_message_id)` 去重：
  - 已存在且已完成：直接返回已保存消息，不重复调用模型。
  - 已存在且处理中：返回冲突提示或复用现有流。
- 重试时使用同一个 `client_message_id`，避免重复消息。

### 7.5 断线与重连

1. 连接中断且未收到 `done`：
   - 前端显示「连接中断，正在重试」。
   - 自动重试最多 2 次，使用同一 `client_message_id`。
2. 仍失败：
   - 消息标记为失败，显示「重新发送」。
   - 后端若已完成，重试会直接返回已保存结果，不重复计费。
3. 页面刷新：
   - 重新加载会话消息，已完成的消息正常展示。
   - 处理中的消息若已超时，标记失败。

## 8. 上下文策略

### 8.1 上下文组成

每次轻链路调用携带：

1. 系统提示词（按 Agent 配置）。
2. 前端从 localStorage 读取的当前参数（商品名称、风格、尺寸、模板），随聊天请求提交，不落库。
3. `requirement_summary`。
4. 最近 **10 轮**对话（用户 + Agent 为一轮）。
5. 已确认示例图的描述（若存在）。

### 8.2 截断规则

- 超过 10 轮时，从最早的一轮开始丢弃。
- 丢弃前保留一条系统摘要：「更早的对话已省略，需求摘要以当前 `requirement_summary` 为准」。
- 若仍超过模型上下文上限，按「先丢历史对话 → 再压缩需求摘要」的顺序处理。
- 具体 Token 上限由模型配置决定，后台可调。

### 8.3 不跨会话

- 不同会话之间不共享上下文。
- 新建会话即清空上下文。
- 切换会话加载对应会话的消息与摘要。

## 9. 与生图流程的衔接

### 9.1 聊天不触发生成

- 聊天仅更新需求与摘要，不创建生成批次。
- 生成必须由用户点击「生成示例图」或「确认并生成全套」。

### 9.2 生成时的输入

生成示例图时，全链路使用：

- 参数面板快照。
- `requirement_summary`。
- 最近 10 轮聊天摘要。
- 上传的商品图。
- 选中的模板。

### 9.3 示例确认后的聊天

- 示例确认后，用户仍可继续聊天。
- 若聊天中改变了关键需求（风格、卖点、尺寸），界面提示「需求已变化，建议重新生成示例图」。
- 用户点击「重新生成示例」后，创建新的 `sample` 批次；已确认的全套结果不受影响。
- 不支持在已生成的全套结果上直接局部修改。

## 10. 异常与提示

| 场景 | 提示 | 处理 |
| --- | --- | --- |
| 商品名称未填 | 请先填写商品名称后再开始对话 | 输入框禁用 |
| 消息为空 | 请输入内容 | 阻止发送 |
| 超长 | 消息不能超过 2000 个字符 | 阻止发送 |
| 发送中重复发送 | 正在回复中，请稍候 | 按钮禁用 |
| 模型调用失败 | 回复失败，请重试 | 消息标记失败 + 重试 |
| 内容审核不通过 | 内容未通过审核，请调整后重试 | 消息标记失败 |
| 连接中断 | 连接中断，正在重试 | 自动重试 2 次 |
| 会话不存在/无权限 | 会话不存在或已删除 | 返回列表/提示 |
| 登录过期 | 登录已过期，请重新登录 | 跳转登录 |

## 11. 权限与数据

1. 仅拥有普通用户角色的账号可使用聊天。
2. 用户只能访问自己的会话与消息。
3. 管理员可在后台查看任意用户的会话与消息，但不能在后台替用户发消息。
4. 聊天记录长期保存，随业务数据执行 5 年热存 + 归档策略。
5. 用户软删除会话后，消息仍保留在数据库与 MinIO（如有附件）。
6. 聊天记录不提供导出。

---

## 12. 验收标准

1. 商品名称未填时聊天输入框禁用；填写后可用，其余字段选填。
2. 发送消息后用户气泡立即上屏，Agent 回复流式展示。
3. 每条消息只调用规划 Agent 与商品理解 Agent，不触发生图。
4. 会话可按首条消息或商品名称自动命名，可重命名。
5. 会话可软删除，删除后用户列表隐藏、后台仍可查。
6. 上下文只保留最近 10 轮，超限从最早轮次丢弃。
7. 断线自动重试最多 2 次，重试不产生重复消息。
8. 聊天中改变关键需求时提示重新生成示例图。
9. 聊天记录在后端可按消息查看 Agent 调用明细与 Token。
10. 未登录、越权访问他人会话时返回 401/403。
