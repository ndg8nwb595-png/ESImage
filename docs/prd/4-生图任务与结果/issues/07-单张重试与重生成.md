# 07: 单张重试与重生成

**What to build:** 用户可以对 `completed` / `partially_failed` 全套批次中的单张图片发起重试或重生成。后端创建新的图片记录，`index_no` 不变、`attempt_no` 加 1，旧记录标记 `superseded`；新记录完全沿用该张原提示词、负面提示词与模型参数，不支持用户微调。新图只执行生图 → 生成图内容审核 → 质量审核（含修复复检）→ 平台规范 → 文字合成，不重新调用规划、商品理解、文案、提示词 Agent。成功后新图替换结果区展示，旧图保留在后台；失败张重试成功后批次可由 `partially_failed` 回到 `completed`。

**Blocked by:** 05（失败重试、降级与部分失败）

**Status:** ready-for-agent

- [ ] `POST /api/v1/images/{image_id}/regenerate` 仅允许当前用户操作自己的图片；图片不存在或不属于当前用户返回 404 `30014`。
- [ ] 只允许 `full` 批次中 `image_type=final`、且是当前最新尝试（非 `superseded`）的图片；示例图、`superseded` 旧图返回 409 `30005`。
- [ ] 只允许批次状态为 `completed` 或 `partially_failed`；`queued`、`running`、`failed`、`cancelled`、`confirmed` 返回 409 `30005`，并提示「请从批次入口重新生成」。
- [ ] 同一批次同时只允许一个重试/重生成任务；已有图片处于 `generating` 时再次提交返回 409 `30005`，由行锁或批次级检查保证。
- [ ] 请求带 `client_request_id`；同一请求重复提交返回已创建的新图片，不重复创建、不重复调用模型。
- [ ] 新记录复制原图的 `batch_id`、`user_id`、`session_id`、`image_type`、`image_role`、`index_no`、`prompt`、`negative_prompt`、`model_name` 参数；`attempt_no` 为同 `index_no` 当前最大尝试号加 1，初始 `status=pending`。
- [ ] 旧记录在同一事务内置 `superseded`、`is_history_visible=false`；新记录创建后返回新 `image_id`、批次 ID、序号、角色、尝试号与 `pending` 状态。
- [ ] 新图执行：生图（最多 2 次）→ 生成图内容审核 → 质量审核（含修复复检）→ 平台规范 → 文字合成；失败策略与 05 一致。
- [ ] 重试/重生成期间批次 `stage` 依次更新为 `image_generator`、`quality_reviewer`、`platform_rule`、`text_composition`，完成后回到 `done`；批次 `status` 在该张结束前保持原终态，结束后按当前图片结果重新汇总。
- [ ] 新图成功：写入文件、缩略图、尺寸、模型名、耗时、Token，`status=success`，`is_history_visible=true`；结果区只展示新图，`index_no` 不变。
- [ ] 新图失败：记录失败原因，`is_history_visible=false`；批次按当前成功图数量重新汇总，可能由 `completed` 变为 `partially_failed`。
- [ ] `completed_count` 按当前非 `superseded` 的成功图数量重新计算：失败张重试成功后加 1；成功张重生成成功后保持不变；成功张重生成失败后减 1；不得小于 0、不得大于 `total_count`。
- [ ] 批次内全部当前图片成功时，批次置 `completed`；部分成功置 `partially_failed`；全部失败置 `failed`；`finished_at` 按需更新。
- [ ] 前端对 `failed` 图展示「重试」，对 `success` 图展示「重生成」；不提供提示词、尺寸、字体等参数编辑；操作中展示 loading 并禁止重复点击。
- [ ] 每次生图、内容审核、质量审核、修复、平台规范调用写 `agent_runs`，关联新 `image_id` 与批次；不新增规划、商品理解、文案、提示词记录。
- [ ] 本切片不改变批次总数、不新建批次、不重新生成主图文件本身；第 1 张主图也可重试/重生成，但示例图本身不可操作。
