## 1. 文档目的与范围

### 1.1 目的

定义从「点击生成示例图」到「拿到一整组正式图」的完整链路：批次模型、8 Agent 全链路、示例确认、批量生成、文字合成、失败降级、结果下载，以及生成所依赖的模板/素材库/尺寸预设配置管理。

### 1.2 本期范围

- 生成输入与参数快照。
- `sample` 示例批次与 `full` 全套批次。
- 批次与单图状态机。
- 8 Agent 的职责、输入输出、调用顺序、失败降级。
- 示例图确认循环与全套批量生成。
- 模型留白 + 后端文字合成。
- 单张重试、整批局部失败、取消任务。
- 结果下载与文件命名。
- 模板、素材库、尺寸预设的生成配置管理（管理员/超管）；风格由用户填写或 Agent 推荐，不做后台配置。

### 1.3 不做

- 局部重绘、涂抹修复、在线改字。
- 一次提交多个商品。
- 用户自定义提示词、字体、颜色。
- 批量生成多个规格。
- 生成视频、3D 素材。

## 2. 生成输入与参数快照

### 2.1 输入组成

| 输入 | 来源 | 必填 |
| --- | --- | --- |
| 商品名称 | 参数面板，用户手填 | 是 |
| 风格 | 参数面板，自由文本；不填由 Agent 推荐 | 否 |
| 尺寸 | 参数面板，平台预设或自定义；不选默认 1:1 | 否 |
| 商品图 | 参数面板上传，0~5 张 | 否 |
| 模板 | 模板卡片，可选 | 否 |
| 需求摘要 | 会话 `requirement_summary` | 否 |
| 聊天摘要 | 会话最近 10 轮 | 否 |
| 会话 ID | 当前创作会话 | 是 |

### 2.2 参数快照

- 创建批次时，后端把上述输入固化为 `params_snapshot`（JSONB）。
- 快照至少包含：商品名称、风格文本、宽高、图片构成（1 主图 + 5 详情图）、模板 ID 与名称、上传图 ID 列表、需求摘要、创建时间。
- 生成过程中前端修改参数不影响已创建批次。
- 后台追溯时以快照为准，不以当前配置为准。

### 2.3 参数校验

- 前端校验：商品名称为空、尺寸非法、上传超限时拦截，不发送请求。
- 后端校验：
  - 商品名称 1~60 字符。
  - 风格为选填自由文本，填写时 1~50 字符。
  - 尺寸选填；未选时使用 1000×1000。
  - 上传图属于当前用户且未被删除。
  - 模板与图片角色匹配。
  - 用户没有进行中的生成批次。
- 校验失败返回参数错误，不创建批次。

## 3. 批次模型与状态机

### 3.1 批次类型

| 类型 | `batch_type` | 说明 | 张数 |
| --- | --- | --- | --- |
| 示例批次 | `sample` | 生成 1 张主图作为设计风格示例图，等待用户确认 | 1 |
| 全套批次 | `full` | 确认示例后生成完整一组 | 1 主图 + 5 详情图 = 6 |

### 3.2 批次关系

- 每个 `sample` 批次只产出 1 张示例图。
- 用户可多次生成示例，每次创建新的 `sample` 批次；旧批次保留可追溯。
- 用户确认某个 `sample_ready` 批次后，系统创建 `full` 批次，`source_sample_batch_id` 指向该示例批次。
- `full` 批次把被确认的示例图作为主图，不重复生成，然后生成 5 张详情图，共 6 张。

### 3.3 示例批次状态

```
queued → running → sample_ready → confirmed
                 ↘ failed
queued / running / sample_ready → cancelled
```

| 状态 | 说明 |
| --- | --- |
| `queued` | 已创建，等待 Worker |
| `running` | 正在执行 Agent 链路 |
| `sample_ready` | 示例图已生成，等待用户操作 |
| `confirmed` | 用户已确认，已创建 `full` 批次 |
| `failed` | 生成失败 |
| `cancelled` | 用户取消 |

### 3.4 全套批次状态

```
queued → running → completed / partially_failed / failed
queued / running → cancelled
```

| 状态 | 说明 |
| --- | --- |
| `queued` | 已确认，等待 Worker |
| `running` | 正在批量生成 |
| `completed` | 全部成功 |
| `partially_failed` | 部分成功、部分失败 |
| `failed` | 全部失败 |
| `cancelled` | 用户取消 |

### 3.5 单图状态

```
pending → generating → success / failed
                    ↘ cancelled
```

- 失败张可单独重试；若生图模型 2 次失败导致整批失败，则需从批次入口重新生成。
- 重试或重生成创建新的图片记录，旧记录标记 `superseded`。
- 只有 `success` 且属于 `completed` / `partially_failed` 全套批次的正式图，才进入历史作品。

### 3.6 状态机约束

1. 同一用户同时只允许 1 个 `queued` / `running` / `sample_ready` 批次。
2. `confirmed` 只能从 `sample_ready` 进入。
3. `full` 批次必须引用一个 `confirmed` 的 `sample` 批次。
4. `cancelled` 是终态，不允许恢复。
5. `success` 的单图不允许回退状态；重生成另建记录。

## 4. 8 Agent 全链路

### 4.1 Agent 清单

| 顺序 | Agent | `agent_code` | 核心 | 失败策略 |
| --- | --- | --- | --- | --- |
| 1 | 规划 Agent | `planner` | 是 | 重试 10 次；仍失败则任务失败 |
| 2 | 商品理解 Agent | `product_understanding` | 是 | 重试 10 次；仍失败则任务失败 |
| 3 | 文案 Agent | `copywriter` | 是 | 重试 10 次；仍失败则任务失败 |
| 4 | 提示词 Agent | `prompt_builder` | 是 | 重试 10 次；仍失败则任务失败 |
| 5 | 生图执行 Agent | `image_generator` | 是 | 最多尝试 2 次；2 次失败整个任务失败 |
| 6 | 质量审核 Agent | `quality_reviewer` | 否 | 重试 10 次；仍失败跳过并标记「未校验」 |
| 7 | 修复 Agent | `repairer` | 否 | 重试 10 次；仍失败跳过并标记「未修复」 |
| 8 | 平台规范 Agent | `platform_rule` | 否 | 重试 10 次；仍失败跳过并标记「未校验」 |

> 除生图执行 Agent 外，重试采用指数退避：1s → 2s → 4s → 8s → 16s → 30s 封顶。

> 素材检索是商品理解 Agent 内部调用的工具，不单独计为 Agent。

### 4.2 调用顺序

```
规划
  ↓
商品理解（含素材检索）
  ↓
文案
  ↓
提示词
  ↓
生图执行
  ↓
质量审核
  ↓（不通过）
修复 → 生图执行（最多 1 次）
  ↓
平台规范
  ↓
文字留白合成
  ↓
输出
```

### 4.3 各 Agent 职责与输出

#### 4.3.1 规划 Agent

**输入**：参数快照、需求摘要、最近 10 轮聊天摘要、聊天意图、模板信息。

**输出**：任务计划 JSON。

```json
{
  "image_count": 6,
  "images": [
    {
      "index": 1,
      "role": "main",
      "theme": "白底商品主视觉",
      "copy_focus": "整体外观与品牌感",
      "layout_hint": "标题上方，卖点下方"
    },
    {
      "index": 2,
      "role": "detail",
      "theme": "核心卖点",
      "copy_focus": "面料与版型",
      "layout_hint": "左图右文"
    }
  ],
  "order": ["product_understanding", "copywriter", "prompt_builder", "image_generator"]
}
```

- `images` 数组固定 6 项：1 个 `role=main` + 5 个 `role=detail`。
- 每张图的主题由规划 Agent **动态决定**，不套用固定主题清单。
- 主题需符合图片角色（主图/详情图）与电商场景，避免重复。
- 全套批次的计划可复用被确认示例批次的计划，保持风格一致。

#### 4.3.2 商品理解 Agent

**输入**：商品名称、上传商品图（视觉理解）、需求摘要、聊天摘要。

**输出**：商品画像 JSON。

```json
{
  "category": "服饰鞋包",
  "selling_points": ["透气", "不易起球", "百搭"],
  "target_audience": "25~35 岁通勤女性",
  "scenes": ["办公室", "周末出行"],
  "constraints": ["不要出现真人正脸"],
  "material_ids": [12, 18]
}
```

- 调用素材检索工具，从素材库挑选背景/场景候选。
- 不传商品图时，仍可根据名称与描述生成画像，但需标注「无实物参考」。

#### 4.3.3 文案 Agent

**输入**：商品画像、每张图主题、风格、模板文案结构。

**输出**：每张图的文案块。

```json
{
  "index": 1,
  "title": "轻盈透气 一整天",
  "selling_points": ["冰感面料", "不易起球", "通勤百搭"],
  "body": "适合日常通勤的轻薄款",
  "tone": "简洁有力"
}
```

- 文案为简体中文。
- 标题建议 6~12 字，卖点每条 4~10 字，避免超出排版区。
- 不生成价格、促销倒计时等未经用户提供的信息。

#### 4.3.4 提示词 Agent

**输入**：文案块、商品画像、风格、尺寸、模板、素材候选。

**输出**：每张图的生图提示词 JSON。

```json
{
  "index": 1,
  "prompt": "电商主图，浅色背景，商品居中，柔和棚拍光，留出上方标题区和下方卖点区",
  "negative_prompt": "文字乱码，水印，低清晰度，主体变形",
  "whitespace": {
    "top_ratio": 0.18,
    "bottom_ratio": 0.22
  },
  "reference_asset_ids": [12],
  "model_params": {
    "width": 1000,
    "height": 1000
  }
}
```

- 必须显式要求留白区，供后端合成文字。
- 不把大段中文文案写进生图提示词，避免模型直接画字。
- 参考图权重、随机种子等高级参数本期不向用户暴露，由后端配置。

#### 4.3.5 生图执行 Agent

**输入**：提示词 JSON、上传商品图、参考素材。

**输出**：基础图文件（未合成文字）。

- 调用豆包 Seedream 图生图；无上传图时走文生图。
- 每张图记录：模型名、耗时、状态、错误信息、Token（如接口返回）。
- 单张超时 120 秒。
- 失败最多尝试 2 次；2 次失败整个任务失败。

#### 4.3.6 质量审核 Agent

**输入**：基础图、商品画像、提示词。

**输出**：审核结果。

```json
{
  "passed": true,
  "issues": [],
  "checks": {
    "product_fidelity": "pass",
    "deformity": "pass",
    "whitespace_available": "pass",
    "compliance": "pass"
  }
}
```

- 使用豆包视觉模型。
- 检查：商品是否变形、留白区是否可用、是否出现违规内容。
- 文字正确性由后端合成保证，不由视觉审核负责。
- 不通过时交给修复 Agent。

#### 4.3.7 修复 Agent

**输入**：审核问题、原提示词、商品画像。

**输出**：修正后的提示词 JSON。

- 最多修复 1 次。
- 修复后重新调用生图执行。
- 仍不通过则标记该张失败，原因写「质量问题未通过」。

#### 4.3.8 平台规范 Agent

**输入**：文案、尺寸、商品类目。

**输出**：规范检查结果。

```json
{
  "passed": true,
  "issues": [],
  "checks": {
    "size": "pass",
    "prohibited_words": "pass",
    "category_rules": "pass"
  }
}
```

- 检查尺寸是否符合平台要求、文案是否含违禁词、类目是否有特殊限制。
- 不通过时标记该张失败，提示用户调整文案或参数；不自动重试。

## 5. 示例图阶段

### 5.1 创建示例批次

1. 用户点击「生成示例图」。
2. 后端校验参数与并发限制。
3. 创建 `sample` 批次，`total_count=1`，状态 `queued`。
4. 写入参数快照与需求摘要。
5. 返回 `batch_id`，前端开始轮询进度。

### 5.2 执行

1. Worker 取出批次，状态置 `running`。
2. 依次执行规划 → 商品理解 → 文案 → 提示词 → 生图执行 → 质量审核 → 平台规范 → 文字合成。
3. 成功后创建 1 条 `generated_images` 记录，`image_type=sample`，`status=success`。
4. 批次状态置 `sample_ready`。

### 5.3 用户操作

| 操作 | 行为 |
| --- | --- |
| 重新生成示例 | 创建新的 `sample` 批次，使用当前参数与最新需求摘要；旧批次保留 |
| 调整参数 | 回到参数面板，不创建批次；修改后需再次点击生成 |
| 确认并生成全套 | 创建 `full` 批次，引用当前 `sample_ready` 批次 |

### 5.4 重复生成示例

- 每次点击「重新生成示例」都创建新的 `sample` 批次。
- 结果区只展示最新 `sample_ready` 批次的示例图。
- 旧示例批次状态保持不变（`sample_ready` 或 `failed` / `cancelled`），供后台追溯。
- 只有最新一次 `sample_ready` 的示例可以确认；旧示例不能确认。

### 5.5 示例图属性

- 示例图是正式风格的代表，不是缩略草稿，分辨率与正式图一致（1000×1000）。
- 示例图在确认前不可下载。
- 确认后作为 `full` 批次第 1 张正式图。

## 6. 全套生成阶段

### 6.1 创建全套批次

1. 用户点击「确认并生成全套」，二次确认。
2. 后端校验：
   - 示例批次属于当前用户。
   - 示例批次状态为 `sample_ready`。
   - 示例批次是最新可确认批次。
   - 用户没有进行中的批次。
3. 创建 `full` 批次：
   - `batch_type=full`
   - `source_sample_batch_id=<示例批次>`
   - `total_count=6`（1 主图 + 5 详情图）
   - `completed_count=1`（示例图）
   - 状态 `queued`
4. 示例批次状态置 `confirmed`。

### 6.2 复用示例结果

- 被确认的示例图直接作为 `full` 批次第 1 张正式图：
  - 新建一条 `generated_images` 记录，`batch_id=full 批次`、`image_type=final`、`index=1`。
  - 文件路径复用示例图，不重新生成。
  - 记录 `source_image_id` 指向示例图。
- 规划、商品理解、文案、提示词可复用示例批次的输出，保持风格一致。
- 剩余 5 张详情图逐张生成。

### 6.3 批量执行

1. Worker 取出 `full` 批次，状态 `running`。
2. 按规划顺序逐张生成：
   - 同一批次内**串行**生成，降低供应商限流风险。
   - 每张完成后更新 `completed_count`。
3. 单张成功：`generated_images.status=success`。
4. 单张生图失败：同一张最多尝试 2 次；2 次失败整个批次立即 `failed`。
5. 非生图原因（审核/合成/规范）导致的单张失败：标记该张 `failed`，继续下一张。
6. 全部结束：
   - 全部成功 → `completed`
   - 部分成功 → `partially_failed`
   - 全部失败 → `failed`

### 6.4 生成进度

- 前端每 2 秒轮询 `GET /api/v1/generations/{batch_id}`。
- 返回阶段、已完成张数、总张数、当前图片状态。
- 阶段展示：需求理解 → 文案生成 → 提示词构建 → 图像绘制 → 质量审核 → 文字合成。
- 轮询在页面隐藏时降低频率（如 10 秒），恢复可见后立即刷新。

## 7. 文字留白与后端合成

### 7.1 设计原则

- 生图模型只负责画面，**不负责写中文**。
- 提示词中要求模型留出文字区。
- 后端使用中文字体与版式把文案合成到图上，保证文字正确、可控。

### 7.2 合成输入契约

由设计 Skill 或默认版式生成 `layout_instruction`：

```json
{
  "canvas": { "width": 1000, "height": 1000 },
  "blocks": [
    {
      "type": "title",
      "text": "轻盈透气 一整天",
      "box": { "x": 80, "y": 70, "width": 840, "height": 120 },
      "font_size": 64,
      "font_weight": "bold",
      "color": "#1A1A1A",
      "align": "center"
    },
    {
      "type": "selling_points",
      "items": ["冰感面料", "不易起球", "通勤百搭"],
      "box": { "x": 100, "y": 760, "width": 800, "height": 160 },
      "font_size": 36,
      "color": "#333333",
      "align": "center"
    }
  ]
}
```

### 7.3 合成输出契约

- 输入：基础图、`layout_instruction`。
- 输出：合成后的 PNG。
- 失败时：该张图片标记失败，原因「文字合成失败」。
- 字体：后端内置 1~2 个可商用中文字体，用户不可选。
- 文案超长：自动缩小字号至下限；仍超出则截断并记录警告，不阻塞出图。
- 文字区背景：若基础图留白不足，允许加半透明色块保证可读性。

### 7.4 设计 Skill 未产出时的兜底

- 使用默认版式：
  - 标题居中放在上方 15% 区域。
  - 卖点放在下方 20% 区域，最多 3 条。
  - 左右安全边距 8%。
  - 深色文字配浅色底，必要时加半透明白底。
- 设计 Skill 产出后替换默认版式，不改变本节的输入输出契约。

## 8. 失败、重试、降级与取消

### 8.1 Agent 失败

1. 除生图执行 Agent 外，每个 Agent 调用失败自动重试 **10 次**，采用指数退避（1s → 2s → 4s → 8s → 16s → 30s 封顶）。
2. 生图执行 Agent 每张最多尝试 **2 次**；2 次均失败，整个任务立即失败。
3. 其他 Agent 重试 10 次仍失败：
   - 核心 Agent（规划、商品理解、文案、提示词）：批次失败，记录失败阶段与错误信息，前端提示卡点。
   - 非核心 Agent（质量审核、修复、平台规范）：跳过，继续后续流程，并在批次/图片上标记「未校验」「未修复」等状态。

### 8.2 单张失败

- 生图执行失败：同一张最多尝试 **2 次**。
- 2 次均失败：整个任务立即失败，批次状态 `failed`，不再生成其他张。
- 非生图原因（内容审核、文字合成、平台规范）失败：该张 `status=failed`，记录原因，继续其他张；批次结束后为 `partially_failed`。
- 用户可在结果区对失败张点「重试」，创建新的图片记录；若整批已失败，则从批次入口重新生成。

### 8.3 内容审核失败

- 上传图或生成图被内容审核拦截：
  - 上传图：阻止上传，提示更换。
  - 生成图：该张失败，提示「内容未通过审核，请调整描述或更换商品图」。
- 不自动反复重试，避免持续触发审核。

### 8.4 取消任务

- 可取消状态：`queued`、`running`、`sample_ready`（示例批次）；`queued`、`running`（全套批次）。
- 取消后：
  - 批次状态置 `cancelled`。
  - 停止创建新的图片任务。
  - 已在生成中的单张允许完成，但结果不进入历史作品。
  - 已成功的图片保留在后台记录中，标记为取消任务产物。
- 取消需二次确认。

### 8.5 超时

- 单张生图超时 120 秒，按失败处理；同一张最多尝试 2 次。
- 其他 Agent 单次调用超时按失败处理，进入 10 次重试。
- 整批超时 **30 分钟**；未完成部分标记失败。生图环节未完成则批次置 `failed`，否则按实际结果置 `partially_failed`。
- 超时原因记录到批次错误信息。

### 8.6 重复提交

- 前端在批次进行中禁用生成按钮。
- 后端用 `client_request_id` 做幂等：同一请求重复提交返回已有批次，不重复创建。
- 同一用户并发创建批次返回业务错误「已有生成任务进行中」。

## 9. 结果区与下载

> 用户端结果区的布局与状态详见 `2-用户端创作工作台prd.md` 第 9 章，本节定义数据与文件规则。

### 9.1 结果组成

| 批次 | 结果 |
| --- | --- |
| 示例批次 | 1 张主图示例（确认前不可下载） |
| 全套批次 | 1 张主图 + 5 张详情图，共 6 张，含复用的示例图 |

### 9.2 历史可见性

- `generated_images.is_history_visible` 为真：
  - 属于 `full` 批次；
  - `image_type=final`；
  - `status=success`；
  - 批次状态为 `completed` 或 `partially_failed`。
- 示例图、失败图、取消任务半成品、被替代的旧图均不可见。

### 9.3 单张下载

- 格式：PNG。
- 文件名为 `{商品名称}_{主图|详情图}_{序号}_{yyyyMMddHHmmss}.png`。
- 示例图确认前不可下载；确认后作为正式图可下载。

### 9.4 整组下载

- 仅 `full` 批次可整组下载。
- ZIP 内容：
  - 全部成功图片，按序号命名。
  - `manifest.csv`：序号、文件名、状态、尺寸、生成时间、失败原因（如有）。
- ZIP 文件名：`{商品名称}_全套_{yyyyMMddHHmmss}.zip`。
- 部分失败时，ZIP 仍可下载成功图片，并在 manifest 中列出失败张。

### 9.5 重生成与重试

- 重生成某张：仅针对 `full` 批次中的图片；创建新图片记录，沿用该张主题与提示词，允许微调；旧图标记 `superseded`。
- 重试失败张：等同于重生成，但使用原提示词。
- 新图成功后：
  - `index` 不变；
  - `attempt_no` 加 1；
  - 旧图不再在结果区展示，但保留在后台。
- 重生成不改变批次总数与 `completed_count`。

## 10. 生成配置管理（模板 / 素材库 / 尺寸）

> 本节属于管理后台「素材与模板」菜单，权限为管理员 + 超管。用户端只读使用启用中的配置。

### 10.1 模板管理

#### 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 1~50 字符 |
| 适用图片角色 | 是 | 主图 / 详情图 |
| 风格文案 | 否 | 自由文本，作为默认风格 |
| 缩略图 | 是 | JPG/PNG/WEBP，≤10MB |
| 提示词模板 | 否 | 作为提示词 Agent 的参考 |
| 版式参考 | 否 | 供设计 Skill/默认版式参考 |
| 排序 | 否 | 数字，越小越靠前 |
| 状态 | 是 | 启用 / 停用 |

#### 规则

- 新增、编辑、启用/停用、排序。
- 不做物理删除；被停用的模板不再出现在用户端。
- 已被批次引用的模板，其快照保存在 `params_snapshot`，模板后续修改不影响历史记录。
- 列表支持按图片角色、状态筛选。

### 10.2 素材库

#### 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 1~50 字符 |
| 图片 | 是 | JPG/PNG/WEBP，≤10MB |
| 标签 | 否 | 类目、风格等，多个 |
| 排序 | 否 | 数字 |
| 状态 | 是 | 启用 / 停用 |

#### 规则

- 支持上传、编辑、启用/停用、排序。
- 素材用于商品理解 Agent 的场景/背景检索。
- 停用后不再被检索。
- 不做物理删除，避免破坏历史引用。

### 10.3 风格规则（不做后台配置）

- 风格由用户在参数面板自由填写，后台不维护风格配置，也不设风格管理页。
- 用户未填写时，规划 Agent 在聊天中列出 3~5 个适合该商品的风格建议，用户可用自然语言选择或自行补充。
- 风格文本随参数快照写入生成批次，历史记录不受后续对话影响。
- 模板可携带一段风格文案作为默认值，用户可覆盖。

### 10.4 尺寸配置

#### 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 平台名称 | 是 | 如淘宝/天猫、京东、拼多多、抖音 |
| 宽 | 是 | 正整数 |
| 高 | 是 | 正整数 |
| 排序 | 否 | 数字 |
| 状态 | 是 | 启用 / 停用 |

#### 规则

- 内置平台预设均为 1000×1000。
- 管理员可新增、编辑、启用/停用。
- 用户端始终保留「自定义宽高」。
- 自定义宽高的可用范围由后端按豆包模型能力校验。

### 10.5 配置缓存

- 用户端读取启用中的尺寸、模板、素材配置，可缓存 60 秒。
- 后台修改后 60 秒内生效；需要立即生效时可手动刷新缓存。
- 配置变更写入操作日志。

### 10.6 权限

| 操作 | 管理员 | 超管 |
| --- | --- | --- |
| 查看模板/素材/尺寸 | ✓ | ✓ |
| 新增/编辑/启停/排序 | ✓ | ✓ |
| 物理删除 | ✗ | ✗ |

## 11. 权限与数据边界

1. 只有拥有普通用户角色的账号可以创建生成任务。
2. 用户只能操作自己的批次、图片与上传图。
3. 管理员/超管通过后台查看生成记录，不替用户生成。
4. 生成配置（模板/素材/尺寸）由管理员与超管维护；风格由用户填写或 Agent 推荐。
5. 所有生成记录、Agent 调用、Token 消耗必须落库，供后台追溯。
6. 被引用的模板、素材不物理删除，避免历史记录失真。

## 12. 验收标准

1. 商品名称校验通过后能创建 `sample` 批次，并生成 1 张主图示例。
2. 示例图可反复重新生成，每次创建新 `sample` 批次，旧批次保留。
3. 确认示例后创建 `full` 批次，生成 1 张主图 + 5 张详情图，共 6 张；示例图即主图，不重复生成。
4. 8 个 Agent 按顺序调用，每次调用写入 `agent_runs`。
5. 除生图外，Agent 失败重试 10 次；仍失败时核心 Agent 任务失败并提示卡点，非核心 Agent 跳过并标记。
6. 生图模型每张最多尝试 2 次，2 次失败整个任务失败；非生图原因的单张失败标记后其余继续。
7. 支持取消任务；取消后不再创建新图片，已完成图不进历史。
8. 生图提示词包含留白要求，后端完成文字合成，图上中文正确。
9. 结果区支持预览、单张下载、整组 ZIP、重生成、重试失败张。
10. 历史作品只展示最终成功图。
11. 模板、素材、尺寸可后台维护；风格由用户填写或 Agent 推荐，不做后台配置。
12. 同一用户同时只能有 1 个进行中的批次。
