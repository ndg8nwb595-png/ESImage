# 05: 归档图片读取与降级

**What to build:** 满 5 年转入 `archive/` 前缀的图片，在历史页仍能正常预览、单张下载与进入整组 ZIP。读取归档比热数据慢时，界面显示「正在从归档读取…」；归档文件暂时不可用时，接口返回「文件归档中，请稍后重试」，前端提示并保持可用状态，服务端记录错误日志。列表与网格的缩略图仍从热存储读取。

**Blocked by:** 03（大图预览与单张下载）、04（整组 ZIP 与 manifest.csv）

**Status:** ready-for-agent

- [ ] 大图预览、单张下载与整组 ZIP 读取图片时，若 `archived_at` 非空，从 `archive/{原相对路径}` 读取；否则沿用原路径。
- [ ] 缩略图始终从 `thumbnails/` 热存储读取，不因 `archived_at` 非空而切换路径。
- [ ] 归档读取超时由 `ARCHIVE_READ_TIMEOUT_SECONDS` 配置，默认 60 秒；超时视为归档不可用。
- [ ] 归档文件缺失、超时或存储异常时，预览与单张下载返回 404 `30014`，提示「文件归档中，请稍后重试」；整组下载在整个请求内任一文件不可用时同样返回 30014，不返回残缺 ZIP。
- [ ] 归档不可用时写错误日志，至少包含图片 ID、批次 ID、归档对象路径与错误原因，不记录 token 与敏感信息。
- [ ] 前端大图预览或缩略图请求超过 300ms 未返回时显示「正在从归档读取…」；返回后正常展示，失败时 Toast 提示并保留关闭入口。
- [ ] 列表封面加载较慢时显示占位图与「加载中」，不阻塞其他卡片渲染。
- [ ] 归档批次的卡片、详情、成功张数与普通批次一致；归档不影响可见性、排序与下载权限。
- [ ] 种子数据包含 1 个 `archived_at` 非空的全套批次：原件位于 `archive/generated/{user_id}/{session_id}/{batch_id}/...`，缩略图位于 `thumbnails/`，用于验证预览、单张下载与 ZIP。
- [ ] 不实现每日 03:00 的归档调度、5 年扫描、归档复制与原件删除；这些属于 10 号 §7.2 的正式实现。
- [ ] 归档读取不改变 03、04 已定义的接口字段、文件名规则与 manifest 结构。
