## 1. 最小 demo 范围

### 1.1 做

- 管理后台骨架：`/admin` 布局、「账号与权限」菜单两个 Tab（用户管理 / 角色管理）、独立菜单「操作日志」。
- 补种 23 个权限点与三个固定角色的默认权限；新增超管演示账号 `demo_super`。
- 后端权限中间件：每次请求读取当前用户角色与权限，缺失权限返回 403；超管始终拥有全部权限。
- 用户列表：关键词、角色、状态、创建时间筛选；分页 20/50/100；默认创建时间倒序；空状态与加载失败重试。
- 新建账号：用户名、显示名、初始密码、角色、状态；用户名全局唯一（含已删除）、五种合法角色组合、管理员不能分配超管；bcrypt 存储；写操作日志。
- 编辑账号：显示名、角色、状态；管理员不能编辑超管、不能改自己的角色、不能给他人超管；超管不能移除自己的超管角色；不能降级最后一个可用超管；管理员不能改其他管理员的角色。
- 禁用/启用、软删除/恢复：`token_version` 递增使旧 token 失效；已删除账号不能直接启用；最后超管保护；删除与恢复二次确认；写操作日志。
- 重置密码：8~32 位、两次一致；`token_version` 递增；写操作日志且不记录密码。
- 用户详情：基本信息、统计数据、操作入口；内容入口按钮占位禁用。
- 角色管理：三角色卡 + 按「用户端 / 管理后台」分组的权限树；可编辑普通用户与管理员；超管只读且恒为全部；超管专属权限点拒绝授予；最低权限校验；后保存者覆盖；写操作日志。
- 操作日志：列表（时间范围、操作人、动作、结果筛选，分页，时间倒序）+ 详情抽屉；登录与账号/权限操作均可追溯；不可编辑、不可删除。
- 后端越权拦截：`20005` / `20006` / `20007` / `30009` / `30010` / `30011` / `30015`。

### 1.2 不做

- Redis 权限缓存（每次请求直查 PostgreSQL）。
- Alembic 迁移（建表脚本 + 幂等种子脚本）。
- 用户统计的真实聚合（`creative_sessions` / `generated_images` / Agent 调用等表不在本 demo 内）。
- 用户详情中「查看会话」「查看生图记录」的实际跳转（7 号 PRD 范围）。
- 内容追溯、聊天记录、素材与模板、系统提示词、模型配置、Token 统计、数据导出页面与接口。
- 上述模块对应的操作日志动作（模板/素材/尺寸、模型配置、提示词、导出）。
- 个人中心与用户自助修改密码（`PUT /auth/password` 属登录/个人中心范围）。
- 登录失败锁定、验证码、邮件/短信邀请、密码找回、自定义新建角色、用户组/部门。
- 操作日志 5 年归档与数据导出。
- 角色权限并发冲突检测（按 PRD 采用后保存者覆盖）。
- 手机端适配。

### 1.3 相对 PRD 的最小化取舍

| PRD 要求 | 最小 demo 处理 | 原因 / 影响 |
| --- | --- | --- |
| 权限/账号状态走 Redis 缓存 ≤30 秒 | 每次请求直接查 PostgreSQL | 不引入 Redis；行为更严格（即时生效），不影响演示 |
| Alembic 迁移 | 建表脚本 + 幂等种子脚本 | 降低本地启动成本；正式实现再换 Alembic |
| 累计生成图片数、会话数、Token、失败任务数 | 内容表未建，统一返回 `0`，并返回 `stats_available=false` | 字段结构保留；2/4 号模块接入后替换为真实聚合，接口不变 |
| 用户详情「查看会话」「查看生图记录」 | 按钮禁用占位，提示「内容追溯将在 7 号 PRD 实现后开放」 | 避免做一个假跳转；7 号 PRD 实现后接上 |
| 操作日志 5 年保留、导出 | 不做 | 日志表结构与动作码保留，归档策略属 11 号部署文档 |
| 各模块操作日志（模板/素材/模型/提示词/导出） | 不做 | 对应模块不在本 demo 内；日志页按动作码筛选，后续模块直接写入即可 |
| 超管账号预置 | 新增 `demo_super`（`super_admin`） | 1 号 demo 未预置超管；不预置则角色管理与操作日志无法演示 |
| 最后一个可用超管保护 | 保留 | 属账号边界硬性要求，成本低 |
| 并发冲突检测 | 不做，后保存者覆盖 | PRD 已明确 last-write-wins |
| 管理后台其他菜单 | 不做 | 概览、内容追溯、素材模板、Agent 配置、Token 统计、导出均属其他 PRD |
| 手机端 | 不做 | 管理后台桌面优先 |

## 5. 验收总口径（演示脚本）

最小 demo 完成时，至少能完整演示以下路径：

1. `demo_super` 登录 → 进入 `/admin/accounts`，看到 `demo_user`、`demo_admin`、`demo_dual` 与自己的账号。
2. 输入关键词、选择角色与状态、选择创建时间范围 → 列表按条件过滤；切换每页 50 条；筛选变化后回到第 1 页。
3. 点击「新建账号」→ 用户名重复提交返回「用户名已存在」；选择「超管 + 管理员」返回「角色组合不合法」；用 `demo_admin` 创建超管被拒。
4. 新建 `demo_editor`（普通用户）→ 成功，列表立即出现，操作日志新增 `account.create`。
5. 编辑 `demo_editor` 显示名为「编辑小王」，追加管理员角色 → 保存成功；重新登录后管理后台菜单可见。
6. 用 `demo_admin` 打开超管账号 → 无操作按钮或置灰提示「无权操作超管账号」；接口返回 403 `20006`。
7. 用 `demo_admin` 编辑自己 → 角色字段只读；直接调接口改角色返回 403 `20007`。
8. 禁用 `demo_editor` → 该账号已登录页面下一次请求返回 403 `20004`，被踢回登录页。
9. 删除 `demo_editor` → 状态筛选切到「已删除」可见；用户名不能被新账号复用；恢复后重新可登录。
10. 尝试禁用/删除唯一的可用超管 → 返回 `30011`。
11. 重置 `demo_editor` 密码 → 旧 token 请求返回 401 `20003`；用新密码登录成功。
12. 打开用户详情 → 基本信息正确，统计显示 0 并标注；「查看会话/查看生图记录」按钮禁用。
13. `demo_super` 打开「角色管理」→ 三张角色卡与权限树；取消管理员某项权限并保存 → 该管理员下一次请求即失去对应权限。
14. 给管理员勾选超管专属权限点（如 `admin.audit.view`）→ 保存被拒 `30015`；移除普通用户的 `user.workspace` → 保存被拒。
15. 用 `demo_admin` 访问 `/admin/roles` 与 `/admin/audit-logs` → 页面跳 403，接口返回 403 `20005`。
16. 打开「操作日志」→ 按时间/操作人/动作/结果筛选；点行查看 JSON 详情；密码字段不存在；无编辑/删除入口。

## 6. 待确认项

以下事项在接口文档中给出了 demo 默认口径，正式实现前需要与 9 号、10 号文档统一：

1. **用户/日志不存在与账号状态不允许的错误码**：9 号未定义，demo 暂用 `30017`（用户不存在）、`30018`（账号状态不允许该操作）、`30019`（日志不存在）。
2. **管理员分配超管的错误码**：9 号无专用码，demo 暂用 `20005`；是否新增专用码待定。
3. **角色最低权限校验的错误码**：demo 暂用 `30015`（权限点不可授予该角色），与「超管专属权限点」共用。
4. **审计动作码**：demo 使用 `account.create` / `account.update` / `account.reset_password` / `account.disable` / `account.enable` / `account.delete` / `account.restore` / `role.update`，需与 9 号统一。
5. **统计字段口径**：内容模块接入前固定返回 `0` 并带 `stats_available=false`；接入后是否保留该标志待定。
6. **超管权限存储方式**：demo 不向 `role_permissions` 写入 `super_admin` 行，按角色即时授予全部权限；与 10 号「超管不依赖 `role_permissions`」一致，但种子是否要落行需确认。
7. **用户列表/详情/状态操作的响应结构**：9 号未定义，demo 约定账号操作返回账号对象（删除与重置密码返回 `null`）。
8. **`demo_super` 演示账号**：为演示账号权限管理与操作日志新增；正式环境由部署脚本创建首个超管，不走演示种子。
