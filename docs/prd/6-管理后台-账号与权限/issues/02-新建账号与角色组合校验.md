# 02: 新建账号与角色组合校验

**What to build:** 管理员或超管在用户管理页点击「新建账号」，填写用户名、显示名、初始密码、角色与状态；提交成功后新账号出现在列表并写入操作日志。用户名重复（含已删除账号）、角色组合不合法、管理员分配超管、用户名或密码格式错误都会被后端拒绝，并给出对应提示。

**Blocked by:** 01（管理后台骨架、权限点种子与用户列表）

**Status:** ready-for-agent

- [ ] 新建表单字段：用户名（必填）、显示名（必填）、初始密码（必填）、角色（必填，1~2 个）、状态（必填，默认启用）。
- [ ] 用户名去除首尾空格后必须为 4~20 位字母、数字、下划线；不合法返回 400 `10003`；创建后不可修改。
- [ ] 显示名去除首尾空格后 1~30 个字符；为空返回 400 `10002`，超长返回 400 `10004`。
- [ ] 初始密码 8~32 位；为空返回 400 `10002`，超长或过短返回 400 `10004`；不做复杂度要求。
- [ ] 角色只允许五种组合：`user`、`admin`、`super_admin`、`admin+user`、`super_admin+user`；0 个、超过 2 个或 `super_admin+admin` 返回 409 `30009`。
- [ ] 管理员创建账号时分配 `super_admin` 返回 403 `20005`；超管可分配除禁止组合外的全部角色组合。
- [ ] 用户名与 `users.username` 全局唯一（含已删除账号），重复返回 409 `30010`。
- [ ] 密码以 bcrypt cost=12 写入 `password_hash`；响应与页面都不回显密码，创建后不可查看。
- [ ] 成功后写入 `audit_logs`：`action=account.create`、`target_type=account`、`target_id=用户名`、`result=success`，`detail` 含用户名、显示名、角色、状态，不含密码或哈希。
- [ ] 状态只允许 `active` / `disabled`；传入其他值返回 400 `10003`。
- [ ] 提交成功后关闭弹窗、Toast 成功、列表刷新并出现新账号；失败时 Toast 显示后端 `message` 且保留表单内容。
- [ ] 接口与页面各有可执行的冒烟测试，关键步骤输出中文日志。
