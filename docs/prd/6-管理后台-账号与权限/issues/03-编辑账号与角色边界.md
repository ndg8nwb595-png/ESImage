# 03: 编辑账号与角色边界

**What to build:** 管理员或超管在列表或详情中打开「编辑」，修改显示名、角色、状态并保存；不同操作者与目标账号之间的可改字段按账号边界收紧，越权请求返回对应错误码；修改角色写入操作日志并记录修改前后值，目标用户下一次请求即按新角色鉴权。

**Blocked by:** 02（新建账号与角色组合校验）

**Status:** ready-for-agent

- [ ] 编辑弹窗可改显示名（1~30，去首尾空格）、角色（1~2，组合规则与新建一致）、状态（`active` / `disabled`）；用户名只读。
- [ ] 管理员编辑超管账号返回 403 `20006`；管理员不能把任何账号的角色改为 `super_admin`，返回 403 `20005`。
- [ ] 管理员修改自己的角色返回 403 `20007`；自己的显示名可改。
- [ ] 管理员修改其他管理员的角色返回 403 `20005`；其他管理员的显示名、状态仍可改。
- [ ] 超管移除自己的 `super_admin` 角色返回 403 `20007`；自己的显示名可改。
- [ ] 把最后一个可用超管降级（移除 `super_admin` 或改为非启用状态）返回 409 `30011`。
- [ ] 状态只允许 `active` / `disabled`；通过编辑把状态改为 `deleted` 返回 400 `10003`；已删除账号需走恢复接口。
- [ ] 角色组合不合法返回 409 `30009`；目标账号不存在返回 404 `30017`。
- [ ] 角色变更写入 `audit_logs`：`action=account.update`、`target_type=account`、`target_id=用户名`，`detail` 记录修改前后的显示名、角色、状态。
- [ ] 角色变更在下一次请求生效；前端菜单在刷新或重新登录后更新。
- [ ] 保存成功后列表与详情同步更新；失败时 Toast 显示后端 `message`。
- [ ] 接口与页面各有可执行的冒烟测试，关键步骤输出中文日志。
