# 05: 重置密码与旧 Token 失效

**What to build:** 管理员或超管在列表或详情中点击「重置密码」，弹窗输入新密码与确认密码；成功后该账号的旧 token 立即失效，用户必须用新密码重新登录；操作写入日志且不记录密码内容。

**Blocked by:** 03（编辑账号与角色边界）

**Status:** ready-for-agent

- [ ] 重置密码弹窗包含新密码与确认密码；两者均非空，去除首尾空格后 8~32 位，两次必须一致；不一致或为空时前端提示且不发送请求。
- [ ] 后端再次校验新密码 8~32 位；为空返回 400 `10002`，超长或过短返回 400 `10004`。
- [ ] 成功后用 bcrypt cost=12 覆盖 `password_hash`，`token_version` 递增，不强制用户下次登录修改密码。
- [ ] 重置后该账号的旧 token 下一次请求返回 401 `20003`（版本不符），需重新登录；新密码可正常登录。
- [ ] 管理员不能重置超管密码，返回 403 `20006`；超管不能重置自己的密码，返回 403 `20007`。
- [ ] 管理员可以重置普通用户与其他管理员的密码；超管可以重置除自己以外任何账号的密码。
- [ ] 写入 `audit_logs`：`action=account.reset_password`、`target_type=account`、`target_id=用户名`，`detail` 只含用户 ID 与用户名，不含密码、确认密码或哈希。
- [ ] 成功后提示「密码已重置，请线下告知用户」，关闭弹窗并清空输入。
- [ ] 目标账号不存在返回 404 `30017`。
- [ ] 接口与页面各有可执行的冒烟测试，关键步骤输出中文日志。
