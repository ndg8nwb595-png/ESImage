# 07: 角色管理与权限点配置

**What to build:** 超管在「角色管理」Tab 看到普通用户、管理员、超管三张角色卡与按「用户端 / 管理后台」分组的权限树，可以勾选并保存普通用户与管理员的权限点，保存后立即生效；超管角色卡只读且始终拥有全部权限；超管专属权限点不能被授予其他角色。

**Blocked by:** 01（管理后台骨架、权限点种子与用户列表）

**Status:** ready-for-agent

- [ ] 「角色管理」Tab 仅超管可见；管理员或普通用户访问页面跳 `/403`，接口返回 403 `20005`。
- [ ] `GET /admin/roles` 返回三个角色（`code`、`name`、是否可编辑、当前权限码列表）与 23 个权限点（`code`、`name`、`type`、`group_name`、`is_super_only`）。
- [ ] 普通用户与管理员角色卡可勾选/取消非超管专属权限点；超管卡显示全部权限、全部只读，并提示「超管拥有全部权限」。
- [ ] 超管专属权限点在普通用户/管理员视图中置灰或隐藏，并提示「仅超管可用」。
- [ ] 保存时全量覆盖该角色权限点；授予超管专属权限点返回 409 `30015`。
- [ ] 普通用户角色至少保留 `user.workspace`，管理员角色至少保留 `admin.dashboard.view`；不满足时返回 409 `30015`，提示指明缺失的最低权限。
- [ ] `PUT /admin/roles/super_admin/permissions` 返回 403 `20005`，超管角色权限不可编辑。
- [ ] 不存在的权限码返回 400 `10003`；重复权限码自动去重后保存。
- [ ] 保存写入 `audit_logs`：`action=role.update`、`target_type=role`、`target_id=角色 code`，`detail` 记录修改前后的权限码列表。
- [ ] 保存成功后当前超管下一次请求即按新权限鉴权；其他在线用户在下一次请求生效；前端刷新 `/auth/me` 更新菜单。
- [ ] 不做并发冲突检测，后保存者覆盖先保存者；页面提示「权限变更将覆盖他人的修改」。
- [ ] 接口与页面各有可执行的冒烟测试，关键步骤输出中文日志。
