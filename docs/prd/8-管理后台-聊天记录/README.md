## 1. 最小 demo 范围

### 1.1 做

- 8 号后台菜单骨架：「内容追溯 → 聊天记录」「Agent 配置 → 模型配置（仅超管）」「Agent 配置 → 系统提示词（管理员、超管）」，含路由、菜单可见性与权限拦截。
- 幂等演示种子：4 张内容表的最小建表脚本（已存在则跳过）+ 会话、消息、Agent 调用、生成批次夹具；1 条默认模型配置；8 个 Agent 的初始提示词与版本 1。
- 聊天记录列表：用户、会话标题、消息数、最后消息时间、累计 Token、关联批次、状态；用户关键词、标题关键词、时间范围、状态筛选；分页 20/50/100；默认最后消息时间倒序。
- 可见范围：管理员看不到超管账号的会话；超管可看全部；接口层过滤。
- 会话详情：顶部摘要、按时间正序的消息流、Agent 名称标签、消息 Token、Markdown 基础渲染、关联批次入口；默认加载最新一页，向上滚动加载更早消息。
- 消息定位：搜索命中后进入会话并定位到指定消息（`around_id`），支持前后各加载一段。
- Agent 调用明细：一条 Agent 消息可展开多个调用，展示 Agent、状态、开始时间、耗时、输入/输出 Token、输入/输出摘要、错误、模型；超管可用 `full=true` 查看完整输入/输出，管理员只能看摘要。
- 消息关键词搜索：大小写不敏感子串匹配、仅搜索当前角色可见范围、固定每页 20 条、结果按时间倒序、关键词高亮、点击定位。
- 模型配置（仅超管）：读取与保存服务商、Base URL、API Key、文本/图像/视觉模型、温度、超时、并发、重试、上下文上限；API Key AES-GCM 加密存储、页面脱敏、不可回显、不写日志明文；保存写操作日志。
- 系统提示词：8 个 Agent 列表、当前内容、版本历史、保存新版本、回滚到指定版本；变量建议清单与未知变量提示；保存与回滚写操作日志。
- 只读边界：聊天记录不提供发送、编辑、删除、导出、恢复会话入口。
- 后端越权拦截：`20005`、`30013`、新增 demo 码 `30020` / `30021` / `30022`。

### 1.2 不做

- Redis 权限缓存、Alembic 迁移、Celery、MinIO、Nginx 流式配置。
- 聊天记录导出、消息编辑/删除、管理员替用户发消息、恢复已隐藏会话。
- 消息全文索引（pg_trgm / 全文检索）；本 demo 使用 PostgreSQL `ILIKE`。
- 正则、布尔组合、字段限定搜索。
- 模型配置连通性测试、查看 Key 明文、Key 清除、Key 轮换界面。
- 模型配置真实调用验证；生成/聊天接口不在本 demo 内。
- 提示词 diff、A/B 测试、效果对比；新建/删除 Agent；提示词内容嵌入 Agent 调用明细。
- 概览、Token 统计、生图记录三层钻取、数据导出、素材模板、用户与角色管理页面；这些属 6/7 号 PRD。
- 5 年热存与归档策略；聊天消息存数据库，归档不影响消息查询。
- 手机端适配；管理后台桌面优先。
- 真实 8 Agent 生成链路；本 demo 只展示已落库数据。

### 1.3 相对 PRD 的最小化取舍

| PRD 要求 | 最小 demo 处理 | 原因 / 影响 |
| --- | --- | --- |
| 权限/配置走 Redis 缓存 | 每次请求直查 PostgreSQL；配置保存后立即生效 | 不引入 Redis；行为更严格，不影响演示 |
| Alembic 迁移 | 建表脚本 + 幂等种子脚本 | 降低本地启动成本；正式实现再换 Alembic |
| 聊天数据来自用户真实使用 | 新增幂等种子夹具，固定演示会话/消息/Agent 调用/批次 | 演示稳定、可重复；真实数据接入后直接替换查询源，接口不变 |
| 消息搜索使用 `ILIKE`，数据量大时升级全文检索 | 只做 `ILIKE`，不建 pg_trgm 索引 | 与 10 号 §4.7、8 号 §6.3 一致 |
| 会话详情滚动加载 | `before_id` 游标 + `limit`，默认 20、最大 50 | 不使用分页器；向上滚动加载更早消息 |
| 搜索命中后定位消息 | 会话详情支持 `around_id`，返回锚点前后窗口 | 满足「点击结果进入详情并定位」；不新增分页器 |
| 「查看批次」跳转生图详情 | 会话详情返回关联批次摘要；点击打开只读批次摘要抽屉，完整生图详情待 7 号 demo | 避免本 demo 实现 7 号的三层钻取；PRD 的跳转目标仍保留 |
| 用户链接跳转用户详情 | 链接到 6 号 demo 的 `/admin/accounts/{id}`；6 号未实现时置灰提示 | 复用已有页面，不重复实现用户详情 |
| 模型配置缓存/连通性测试 | 每次读 DB；无连通性测试 | PRD 已明确本期不做连通性测试；保存成功不代表 Key 可用 |
| 模型配置 API Key 加密 | AES-256-GCM，密钥来自环境变量 `MODEL_CONFIG_ENCRYPTION_KEY`；启动缺失即失败 | 与 8 号 §7.2 一致；demo 不提供 Key 轮换工具 |
| 提示词版本对比 | 只提供查看全文与回滚，不做 diff | 与 8 号 §8.4、§12 待确认项一致 |
| 提示词并发保存 | 行锁 + 后保存者覆盖（last-write-wins） | PRD 未要求冲突检测；与 6 号角色权限保存口径一致 |
| 聊天记录 5 年归档 | 不做归档任务；消息留在数据库，可查询 | 归档属 11 号部署与运维；不影响本 demo 的读取逻辑 |
| 管理后台其他菜单 | 不做 | 概览、账号与权限、内容追溯其他模块、素材模板、操作日志页面均属 6/7 号 PRD；本 demo 只写操作日志，不重复做日志页 |

### 2.3 幂等种子夹具

种子脚本重复执行不覆盖已有数据；以 `(user_id, title)` 识别会话，存在则跳过该会话及其消息、Agent 调用、批次。

| 归属 | 会话标题 | 状态 | 消息数 | Agent 调用 | 生成批次 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| `demo_user` | 秋季通勤衬衫 | `active` | 12 | 6 条：`success` / `failed` / `skipped` 混合 | 2 条：`sample` + `full` | 主演示会话；含可展开的 Agent 明细与「查看批次」入口 |
| `demo_user` | 夏季防晒外套 | `hidden` | 6 | 2 条 | 1 条：`sample` | 验证「已隐藏」标签；管理员仍可追溯 |
| `demo_user` | 通勤鞋搭配建议 | `active` | 4 | 2 条 | 0 条 | 验证无关联批次的空状态 |
| `demo_super` | 超管测试会话 | `active` | 2 | 1 条 | 0 条 | 验证管理员看不到超管会话；超管可见 |

- 累计 Token 由 `agent_runs` 的 `prompt_tokens + completion_tokens` 汇总，种子保证与列表展示一致。
- 至少 1 条 Agent 消息通过 `agent_runs.batch_id` 关联批次，用于演示「查看批次」。
- 至少 1 条 `agent_runs` 的 `input_full` / `output_full` 含已脱敏的 `api_key` 占位文本，用于验证后台不回显敏感明文。
- 至少 1 条消息内容包含「衬衫」，1 条包含 `T-shirt`，用于验证子串搜索与大小写不敏感；1 条仅超管会话包含「超管」，用于验证可见范围。

### 2.4 模型配置与提示词种子

- `model_configs` 种入 1 条 `is_active=true` 的默认配置：服务商 `volcengine_ark`、Base URL `https://ark.cn-beijing.volces.com/api/v3`、`text_model` / `image_model` 为演示占位名、`vision_model` 为空、温度 `0.7`、超时 `120`、并发 `4`、重试 `1`、上下文上限 `32000`、API Key 为空。
- `system_prompts` 种入 8 条，`current_version=1`；`prompt_versions` 同步种入每个 Agent 的版本 1，修改人记为种子脚本或 `demo_super`。
- 初始提示词内容为演示占位文本，不作为真实生产提示词；正式接入时由管理员按业务重写并产生新版本。

## 5. 验收总口径（演示脚本）

最小 demo 完成时，至少能完整演示以下路径：

1. `demo_admin` 登录 → 进入 `/admin/chat-records`，看到 `demo_user` 的 3 个会话（含 1 个「已隐藏」），看不到 `demo_super` 的会话。
2. 用用户关键词、会话标题、最后消息时间范围、状态筛选 → 列表按条件过滤；切换每页 50 条；筛选变化后回到第 1 页；默认最后消息时间倒序。
3. 点击「秋季通勤衬衫」→ 顶部摘要显示消息数、累计 Token、关联批次数；消息按时间正序；用户右侧、Agent 左侧、系统居中；Agent 消息带名称标签与 Token。
4. 在消息流顶部向上滚动 → 自动加载更早消息，无分页器；滚动到顶后显示「没有更早的消息」。
5. 点击某条 Agent 消息的「展开 Agent 调用明细」→ 按顺序看到多条调用的 Agent、状态、开始时间、耗时、输入/输出 Token、摘要、模型；失败调用显示错误信息。
6. `demo_admin` 在明细中看不到「查看完整输入/输出」入口；直接请求 `?full=true` 返回 403 `20005`。
7. `demo_super` 打开同一条明细 → 可切换完整输入/输出；内容为已存储文本，不重新调用模型；不出现 API Key 明文、思维链或图片二进制。
8. 点击消息上的「查看批次」→ 打开只读批次摘要抽屉（批次 ID、类型、状态、商品名称、创建时间）；完整生图详情页显示「7 号 PRD 实现后开放」。
9. 在列表顶部搜索「衬衫」→ 结果按消息时间倒序、每页 20 条，摘要中关键词高亮；点击结果进入会话详情并定位到该消息，前后各有上下文。
10. 用 `demo_admin` 直接访问 `/admin/model-config` → 页面跳 403，接口返回 403 `20005`；用 `demo_super` 访问 → 看到模型配置，API Key 为空时显示「未配置」，配置后只显示脱敏值。
11. `demo_super` 修改温度、超时、模型名并保存 → 成功；输入 `temperature=2.5`、`timeout_seconds=10`、空 `text_model` → 分别返回 `10004` / `10004` / `10002`；`api_key` 留空不修改，重新输入则覆盖并只显示后 4 位。
12. 打开 6 号操作日志 → 出现 `model_config.update`，详情只记录变更字段，不出现 Key 明文。
13. `demo_admin` 打开「Agent 配置 → 系统提示词」→ 左侧 8 个 Agent 与当前版本；编辑「规划 Agent」加入 `{{product_name}}` 保存 → 生成版本 2；版本历史可查看版本 1/2 全文。
14. 回滚到版本 1 → 生成版本 3，内容与版本 1 相同；版本 2 仍保留在历史中。
