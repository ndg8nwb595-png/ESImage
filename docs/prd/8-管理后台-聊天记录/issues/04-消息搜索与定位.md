# 04: 消息关键词搜索与定位

**What to build:** 管理员在聊天记录列表顶部输入关键词，得到按消息时间倒序、关键词高亮的结果；结果只包含当前角色可见范围内的消息；点击结果进入会话详情并定位到该消息，前后带上下文。搜索只做大小写不敏感的子串匹配，不做正则、布尔组合、字段限定或导出。

**Blocked by:** 02（会话详情、消息流与消息定位，用于点击结果后的锚点定位）

**Status:** ready-for-agent

- [ ] 搜索接口接收 `keyword`（去除首尾空格后 1~100 字符）、`page`（默认 1）；每页固定 20 条，不开放 `page_size`。
- [ ] 对 `chat_messages.content` 做大小写不敏感的子串匹配；对 `%`、`_`、`\` 做转义；使用 PostgreSQL `ILIKE`，不建 pg_trgm/全文索引。
- [ ] 搜索范围只包含当前角色可见的消息：管理员排除超管账号的会话与消息，超管包含全部；包含 `active` 与 `hidden` 会话。
- [ ] 结果按消息时间倒序、消息 ID 倒序；返回总数、页码、每页条数与结果列表。
- [ ] 每条结果返回：消息 ID、会话 ID、会话标题、会话状态、用户（用户名 + 显示名）、消息角色、`agent_code`、Agent 中文名、消息摘要、消息时间。
- [ ] 摘要为纯文本，去除多余换行，截取命中位置前后共约 120 字符并以省略号标记；不在后端拼接 HTML，前端按关键词做大小写不敏感高亮。
- [ ] 点击结果进入 `/admin/chat-records/{session_id}?around_id={message_id}`，会话详情定位到该消息并加载前后上下文。
- [ ] 关键词为空或全空格返回 400 `10002`；超过 100 字符返回 400 `10004`；无结果返回空列表与总数 0。
- [ ] 不提供正则、布尔组合、字段限定、导出、按用户/Agent/时间二次筛选。
- [ ] 接口与页面各有可执行的冒烟测试，关键步骤输出中文日志。
