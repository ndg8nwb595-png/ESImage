# 02: JWT 鉴权与账号状态校验

**What to build:** 除登录外的每个请求都先经过统一的鉴权闸门：未携带 token、签名错误或 token 版本不符返回 401 `20003`；过期返回 401 `20002`；账号不存在、已禁用或已删除返回 403 `20004`。合法 token 才能进入业务处理。账号状态与权限每次请求直查 PostgreSQL，账号被禁用、删除或重置密码后，旧 token 在下一次请求立即失效。用 `GET /auth/me` 与既有登录接口验证，不新增业务接口。

**Blocked by:** 01（统一响应、错误码与参数校验基线）

**Status:** ready-for-agent

- [ ] `POST /auth/login` 不需要 token；其余所有接口缺少 `Authorization` 头、格式不是 `Bearer <jwt>`、签名错误时返回 401 `20003`，并使用统一错误结构。
- [ ] token 过期返回 401 `20002`；前端按既有约定清除登录态并跳转登录页。
- [ ] token 中 `token_version` 与用户当前 `token_version` 不一致时返回 401 `20003`；重置密码、禁用或其他递增版本的操作用旧 token 请求均被拒绝。
- [ ] 用户不存在、`status=disabled` 或 `status=deleted` 返回 403 `20004`；不返回用户资料、角色或权限。
- [ ] 账号状态校验先于 `token_version` 校验：禁用/删除账号返回 `20004`，而不是 `20003`；该顺序与 6 号 demo 接口文档一致，9 号 §2.2 的文字顺序差异记录在 README §6.2，不在本切片裁决。
- [ ] `GET /auth/me` 返回 `user`、`roles`、`permissions`，且与数据库当前状态一致；token 中的 `roles` / `permissions` 只用于前端展示，后端不信任。
- [ ] `POST /auth/logout` 只写审计日志并返回 `null`，服务端不维护黑名单；退出后的旧 token 在过期前仍可通过鉴权（与 9 号 §4.2 一致）。
- [ ] 鉴权失败不写业务数据、不调用模型、不增加 Token 统计；服务端日志记录请求 ID、用户 ID（若可解析）与失败码，不记录完整 token。
- [ ] 401 与 403 不混用：未登录/过期/无效/版本不符用 401；账号不可用用 403 `20004`。
- [ ] 契约回归套件覆盖无 token、坏签名、过期、版本不符、禁用、删除、正常 active 七种场景，每个用例输出中文日志。
- [ ] 不新增业务接口，不改变 1 号 demo 已定义的 JWT 载荷、有效期与登录响应字段。
