# 03: 权限点校验与越权语义

**What to build:** 每个非登录接口都按 `permissions` 表中的权限码判定：拥有权限码才放行，缺失返回 403 `20005`；`super_admin` 不读 `role_permissions`，直接拥有全部权限；多角色用户的权限是各角色权限并集。普通用户访问管理端接口、管理员访问用户端接口都被拒绝；访问他人的会话、上传图、批次、图片时不泄露资源存在性与内容。权限变更在下一次请求立即生效。

**Blocked by:** 02（JWT 鉴权与账号状态校验）

**Status:** ready-for-agent

- [ ] 每个非登录接口声明一个权限码，或明确标注「登录即可」；权限码与 6 号 demo 的权限点目录一致，不自造新权限码。
- [ ] 普通角色权限取 `user_roles` 关联角色在 `role_permissions` 中的并集；`demo_dual` 同时拥有 `user` 与 `admin` 的权限并集。
- [ ] 角色包含 `super_admin` 时拥有全部权限码，不向 `role_permissions` 写入 `super_admin` 行也能通过；移除 `super_admin` 角色后按普通角色重新判定。
- [ ] 缺少接口所需权限码返回 403 `20005`，`message` 统一为「无权限」；不返回所需权限码、角色名或资源细节。
- [ ] 账号不可用（403 `20004`）先于权限校验；禁用账号不能通过任何业务接口。
- [ ] `demo_user` 请求 `GET /admin/users` → 403 `20005`；`demo_admin` 请求 `GET /sessions` 等用户端接口 → 403 `20005`；`demo_super` 请求两类接口均通过。
- [ ] 用 `demo_user` 请求他人会话消息、上传图、生成批次或图片 → 404 / 403，响应体不含他人数据；不得通过错误文案、总数或字段差异推断资源存在。
- [ ] 权限变更（角色调整、角色权限点保存）在下一次请求立即生效；最小 demo 不接 Redis，每次请求直查 PostgreSQL。
- [ ] 前端从 `GET /auth/me` 获取的 `permissions` 只用于菜单与路由守卫；直接调用越权接口仍由后端返回 403，不依赖前端拦截。
- [ ] 管理员不能通过用户端接口读取超管或普通用户内容；管理端下钻接口的过滤属 7 号 PRD，本切片只保证用户端接口不可越权。
- [ ] 契约回归套件覆盖「用户越权管理端、管理员越权用户端、超管全量、多角色并集、他人资源、权限即时生效」六类场景，每个用例输出中文日志。
- [ ] 不新增业务接口，不改变 1~6 号 demo 已定义的权限码与角色规则。
