# 07: 幂等与并发契约

**What to build:** 网络重试、用户连点或前端重连不会产生重复数据：同一会话内重复的 `client_message_id` 返回已保存消息，不重复调用 Agent、不重复计 Token；首条消息在同一用户下按 `client_message_id` 去重，重复请求返回同一会话；创建生成批次按全局 `client_request_id` 去重，重复请求返回同一 `batch_id`。同一用户同时只能有 1 个 `queued` / `running` 生成批次，`sample_ready` 不占名额；超出并发返回 409 `30003`。

**Blocked by:** 03（权限点校验与越权语义）；2 号 demo 04~05（消息发送与创建示例批次）

**Status:** ready-for-agent

- [ ] 同一会话内重复提交相同 `client_message_id` 的消息 → 返回首次保存的消息，不新增消息行、不新增 Agent 调用记录、不重复计 Token。
- [ ] 首条消息在同一用户下按 `client_message_id` 去重：重复请求返回同一 `session_id` 与同一 `message_id`，不重复创建会话或消息。
- [ ] 重复的 `client_request_id` 创建示例批次 → 返回首次创建的 `batch_id`、`batch_type`、当前 `status`，不重复创建批次、不重复排队、不重复生图。
- [ ] 幂等命中返回的 `id` / `session_id` / `batch_id` 与首次请求一致；状态取当前最新状态，不返回过期快照。
- [ ] 幂等判定与写入在同一事务或数据库唯一约束下完成；两个并发请求同时到达时只能成功写入一条记录，另一个按幂等返回已有记录。
- [ ] 同一用户已有 `queued` 或 `running` 批次时再次创建生成批次 → HTTP 409 `30003`，统一错误结构，`data` 可含当前 `batch_id` 与 `status`。
- [ ] `sample_ready` 状态的示例批次不计入并发，不阻塞新的示例批次或全套批次。
- [ ] 确认全套时，被确认的 `sample_ready` 示例批次不参与并发校验，允许创建 `full` 批次。
- [ ] 并发限制按数据库当前状态判断，不依赖进程内计数器；单实例多线程下同样正确。
- [ ] 同一超管同时只允许 1 个导出任务，超出返回 409 `30008`；本 demo 不实现导出接口，只保留错误码与规则。
- [ ] 幂等命中不重复写审计日志、不重复生成缩略图、不重复推送 SSE 事件；若前端重连，按 3 号 demo 的 `meta.duplicate` 约定重放已保存回复。
- [ ] 契约回归套件用串行重放与并发请求覆盖「消息幂等、首条消息建会话幂等、批次幂等、并发 `30003`、`sample_ready` 不阻塞、确认全套豁免」六类场景，每个用例输出中文日志。
- [ ] 不新增幂等或并发业务接口，不改变 2 号 demo 已定义的幂等键与批次状态机。
